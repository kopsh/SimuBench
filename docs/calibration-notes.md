# 定标场景参考要点

状态：供产品负责人验收定标场景时参考

整理自 Galois Labs 的两篇文章：[Calibration Status in Automated Test Records](https://www.galoislabs.ai/blog/instrument-calibration-test-records) 与 [ISO/IEC 17025 Records for Automated Benches](https://www.galoislabs.ai/blog/iso-17025-automated-test-records)。两篇讨论的是真实测试台上的记录要求；这里只列出对 SimuBench 虚拟仪表与定标场景有影响的部分。条款解释以所在认可机构为准。

## 1. 仪表身份

- 定标与测试脚本通常在运行前读取 `*IDN?`，按序列号与固件版本匹配设备台账（ISO/IEC 17025 第 6.4.13 条把固件版本列为设备身份的一部分）。
- **对 SimuBench 的要求**：每个虚拟仪表实例的厂商、型号、序列号、固件版本可在 Bench 中配置，而不是同型号共用一个固定标识。这样才能：
  - 让脚本的运行前检查在虚拟环境中真实生效；
  - 模拟“借用机替换了原仪表”“固件升级后标识变化”这类情况，验证脚本能否拦截。

## 2. 运行前的校准状态检查

真实脚本常见的检查逻辑（可作为定标场景中被验证的脚本行为）：

- 序列号不在台账中 → 阻止运行；
- 台账状态不是“在用” → 阻止运行；
- 校准到期日早于预计结束时间（而不是开始时间）→ 阻止运行；
- 临近到期（如 14 天内）→ 警告；
- 阻止运行时也写下检查快照，被拒绝的运行同样是证据。

**对 SimuBench 的要求**：定标场景可以附带一份虚拟的校准台账（包含过期、停用、缺失等条目），配合可配置的仪表身份，验证脚本的检查逻辑。

## 3. 定标前后数据与超差

- 证书报告调整前（as-found）与调整后（as-left）的结果；as-found 超差时，需要回溯该仪表自上次合格校准以来的所有测量结果。
- **对 SimuBench 的要求**：虚拟 DUT 的隐藏误差（“隐藏状态即真值”，见 validation-rfgen.md）同时给出 as-found 的真实值；脚本写入定标系数后，as-left 的真实值同样已知，因此平台可以判定脚本的 as-found / as-left 结论是否正确。

## 4. 不确定度与判定规则

- 合格判定应写明判定规则：简单接受，或带保护带的接受（例如保护带等于扩展不确定度 U）。示例：规格 3.2–3.4 V，U = 4 mV，k = 2，保护带 = U 时接受区为 3.204–3.396 V；读数 3.399 V 在简单接受下合格，在保护带规则下“不作符合性声明”。
- **对 SimuBench 的要求**：真值已知，平台可以检查脚本在临界值附近的判定是否符合其声明的规则，这是定标场景最有价值的验收点之一；建议构造真值落在保护带内外两侧的 DUT 个体。

## 5. 运行记录

ISO/IEC 17025 第 7.5、7.11 条对记录的要求，与 D16 的运行记录设计一致，可作为检查清单：

- 保存原始响应（字符串或二进制块），与解析后的值并存；
- 保留全部精度，只在报告中取舍；
- 只追加不覆盖，更正以新记录引用原记录；
- 中止的运行同样保留；
- 记录软件版本、测试序列版本、Bench 版本；
- 记录发起运行的人（脚本或 Agent 发起时，记录安排运行的人与批准版本的人）。

## SimuBench 已提供的能力（M5 基础，D39）

| 要求 | 提供方式 |
| --- | --- |
| 1. 仪表身份可配置 | Bench 中每台仪表可设 `serial`、`firmware`，`*IDN?` 返回实例自己的标识；同型号的两台仪表标识不同 |
| 2. 校准台账与运行前检查 | Bench 的 `assets`：序列号、型号、状态（在用 / 停用 / 隔离 / 报废）、上次校准日期、到期日、证书号；`simubench assets <bench>` 导出 CSV / JSON 供脚本读取；`/api/sessions/{sid}/assets` 与 MCP `read_asset_register` 给出按 Bench 日历计算的剩余天数 |
| 日历 | `run.start` 是虚拟时间 0 对应的日历时刻（默认 2026-01-01T00:00Z，保证可重复）；仪表的 `:SYSTem:DATE?`、`:SYSTem:TIME?` 随虚拟时间走；设置某台仪表的日期只改变它自己的时钟（可模拟时钟设错的仪表） |
| 3. as-found / as-left 与真值 | 万用表 `sb-dmm-1` 的测量通道有隐藏的增益误差（ppm）与零点误差（V），在 Bench 的 `hidden` 中设置；读数 = (真值 × (1 + 增益误差) + 零点误差 − 零点系数) × 增益系数。`:CALibration:SECure:STATe OFF,<安全码>` 解锁，`:CALibration:ZERO?`、`:CALibration:VALue` + `:CALibration?` 调整，`:CALibration:STORe` 计数并记日期，`:CALibration:COUNt?`、`:CALibration:DATE?`、`:CALibration:STRing`；输入与校准值不符时 702、未解锁时 701，系数不能直接写入。隐藏误差即真值，as-found 与 as-left 的真实误差都可计算 |
| 4. 判定规则 | `simubench.engine.calibration`：`decide()` 按简单接受或保护带（默认 = U）给出合格 / 不合格 / 不作符合性声明；`assess()` 用真值判断脚本的声明是否正确（正确、误接受、误拒绝、未声明）。笔记中的例子（3.2–3.4 V，U = 4 mV，读数 3.399 V）作为测试 |
| 5. 运行记录 | D16、D36：原始响应与解析值、只追加、中止的运行同样保留、软件与定义版本（哈希）在记录头部 |

开启 `run.reveal_true_values` 时，万用表的前面板读数接口同时给出真值（`true_DC`、`true_AC`）；验证模式下不开启，脚本无法读到答案。
