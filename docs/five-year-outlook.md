# 五年设想：示波器与频谱仪的目标规格与能力规划

状态：草案（2026-11-13），待产品负责人确认。

本文回答一个问题：**如果要能仿真未来五年会开发的示波器与频谱仪，平台还差什么，按什么顺序补。**
它不替代 [product-plan.md](product-plan.md)（近期顺序与分工）与 [signal-chain.md](signal-chain.md)（信号链方案），而是把它们往后接五年。

两点说明：

- 没有内部的五年指标。第 1 节的规格是**设想**：按公开的行业走向推断的量级，不是厂商路线图，也不是公司规划。拿到真实指标后替换第 1 节，第 2–4 节按同样的方法重排。
- 本文不给日期（roadmap.md 的原则），只给阶段、顺序与完成条件。

## 1. 设想的目标仪表

行业走向的两个判断，决定了下面的规格：

1. **示波器**的竞争点从带宽与采样率转到有效位数、噪声与数字处理功能；前端差异变小，ADC 之后的算法差异变大。
2. **频谱仪**变成宽带矢量信号分析仪：扫频迹线只是一个视图，主体是 IQ 采集、解调与标准测量应用。

每个类别设想三档。档位的意义是**能力的台阶**，不是具体型号。

### 1.1 示波器

| | O1 主流 | O2 高性能 | O3 旗舰 |
| --- | --- | --- | --- |
| 带宽 | 1–2 GHz | 8–25 GHz | 60–110 GHz |
| 采样率 | 5–10 GSa/s | 40–100 GSa/s（交织） | 256 GSa/s |
| 垂直分辨率 | 12 位，高分辨率模式 16 位 | 12 位 | 10–12 位 |
| 存储深度 | 500 Mpts–1 Gpts | 2–4 Gpts | 2–4 Gpts |
| 通道 | 4/8 模拟 + 16 数字 | 4 模拟 | 4 模拟，多台同步 |
| 触发 | 全数字：边沿、脉宽、欠幅、码型、区域 | 加串行码型触发 | 同 O2 |
| 采集 | 分段存储、历史回看 | 同 O1 | 同 O1 |
| 数字处理 | 数学通道、FFT 与频谱视图、光标、自动测量 | 加去嵌、眼图、抖动分析 | 同 O2 |
| 指标的写法 | 噪声、直流增益精度 | 有效位数随频率的曲线、交织杂散 | 同 O2，加通道间时延 |
| 数据出口 | 二进制波形块 | 加高速流式传输 | 同 O2 |

### 1.2 频谱/信号分析仪

| | A1 经济型 | A2 高性能 | A3 旗舰 |
| --- | --- | --- | --- |
| 频率范围 | 9 kHz–8 或 26.5 GHz | 2 Hz–50 GHz | 至 110 GHz，扩频头至 170 GHz 以上 |
| 分析带宽 | 40–160 MHz | 2–4 GHz | 8–10 GHz |
| 实时带宽 | 40–100 MHz | 约 1 GHz | 2 GHz 以上 |
| 相位噪声（1 GHz，10 kHz 偏移） | 约 −105 dBc/Hz | 约 −135 dBc/Hz | 同 A2，互相关后更低 |
| 架构 | 超外差 + 数字中频 | 加宽带直采路径 | 多通道相参接收 |
| 迹线功能 | 多标记、噪声标记、通道功率、邻道功率比、占用带宽、零扫宽 | 同 A1 | 同 A1 |
| 信号分析 | IQ 采集、模拟解调 | 数字解调与 EVM、标准测量应用 | 加互相关 |
| 指标的写法 | 噪声底、三阶截点、平坦度 | 加残余 EVM、宽带无杂散动态范围 | 同 A2 |
| 数据出口 | 迹线、IQ 块 | 加 IQ 长时间流 | 同 A2 |

## 2. 这些规格需要平台具备什么

“现状”一栏的依据：positioning-review.md 第 7 节、component-map.md 缺口清单、architecture.md 2.3 的上限。

| 编号 | 能力 | 哪一档需要 | 现状 |
| --- | --- | --- | --- |
| C1 | 带宽、采样率、位数、频率范围等量级 | 全部 | **具备**：是定义里的参数；库里已有 33 GHz / 128 GSa/s 的示波器与 110 GHz 的频谱仪 |
| C2 | 频谱仪前端非理想：相位噪声、交调、杂散、平坦度 | A1 起 | 进行中（signal-chain.md S9，#954） |
| C3 | 频谱仪采样式求值，ADC 之后全是数字处理块 | A1 起 | 进行中（S10，#955） |
| C4 | ADC 非理想：有效位数随频率下降、非线性、交织失配杂散 | O1 起，O2 是卖点 | 未建模；通用 ADC 块已有，只有量化、削波与噪声 |
| C5 | 示波器的数字处理：数学通道、FFT、光标 | O1 起 | 未建模；S10 的窗与 FFT 块可复用 |
| C6 | 迹线上的测量：多标记、噪声标记、通道功率、邻道功率比、占用带宽、零扫宽 | A1 起 | 未建模（缺口清单二.16，暂不排期） |
| C7 | 时域信号源与瞬态：单次事件、毛刺、突发 | O1 起 | **没有**：网络上的信号是稳态谱线；规划里排在最后（A5、P4-5） |
| C8 | 数字触发族、分段存储、历史回看 | O1 起 | 脉宽触发与分段存储进行中（S13、S14）；其余依赖 C7 才有对象可触发 |
| C9 | 带通信号的表示：载波 + 复包络（宽带调制） | A1 起，A2 是主体 | **没有**：一个信号最多 4095 条谱线，IQ 调制未排期 |
| C10 | IQ 采集与分析带宽 | A1 起 | 未建模；采样流已有 `iq` 帧格式 |
| C11 | 规模：Gpts 级记录、长时间 IQ 流 | O1（深存储）、O2、A2 | 一帧 2²⁶ 点、一次读取 2²⁸ 点、FFT 2²⁰ 点；按帧整块计算 |
| C12 | 数据出口：二进制字节序、分块取回、流式传输 | O1 起 | 波形二进制块具备；字节序与流式传输未排期；HiSLIP 一条消息 1 MiB |
| C13 | 实时频谱：无缝 FFT、概率密度显示、频率模板触发 | A1 起 | 未建模；依赖 C7、C10、C11 |
| C14 | 多通道相参：共本振、通道间相位、互相关 | O3、A3 | 未建模；示波器有通道时延参数 |
| C15 | 结构随配置变化：扩频头、外混频、数字通道插件 | A3、O1 的数字通道 | 选件只能改参数与命令，不能增减组件与端口（D68 的代价） |
| C16 | 数字通道（逻辑信号） | O1 | 没有逻辑介质 |
| C17 | 应用层：数字解调与 EVM、协议解码、眼图、抖动、去嵌 | O2、A2 | 未建模，不计划在平台内重写（见第 5 节） |

读法：C1 具备，C2、C3 与 C8 的一部分在做；**C7（瞬态）与 C9（复包络）是两块地基**，C8、C10、C13、C17 都建在它们上面；C11 是规模，决定 O2 与 A2 能不能跑得动。

## 3. 阶段

每个阶段的完成标志是同一种形式：**一台设想仪表的定义能加载，一份用到该档关键功能的脚本通过**。
设想仪表做成 `sb-*` 验证仪表（放 `validation/instruments/`，不随包发布，D42），不是真实型号，所以不违反
product-plan.md“在 H1–H3 有结果之前不增加新的仪表型号”。

| 阶段 | 内容 | 依赖 | 完成后能仿真 |
| --- | --- | --- | --- |
| 0 收尾 | product-plan.md 的 P1、P3、P4-0：用例对真机运行、信号链第一版余下各项（C2、C3、C8 的脉宽触发与分段存储）、两种求值方式互为对照 | — | 现有型号更接近真机 |
| 1 指标级 | C4 ADC 非理想；C5 示波器的数学通道与 FFT；C6 迹线上的测量与零扫宽 | 阶段 0 的 S10 | O1 与 A1 的**稳态部分**：指标按数据手册出现，常用测量可用 |
| 2 时域与复包络 | C7 时域信号源；C9 带通信号；C8 余下的触发类型与历史回看；C10 IQ 采集 | 阶段 1；先写设计（见 3.2） | O1 完整（除数字通道）；A1 完整（除实时）；A2 的 IQ 采集 |
| 3 规模 | C11 分块求值与编译内核；C12 数据出口；C13 实时频谱 | 阶段 2；按性能分析决定（D19） | O2、A2 的采集与传输 |
| 4 多通道与可变结构 | C14 相参与互相关；C15 选件增减组件；C16 逻辑介质 | 阶段 2 | O3、A3；O1 的数字通道 |
| 应用层（按需） | C17：经算法托管接入，不在平台内重写 | product-plan.md 的 H5、P4-1 | O2、A2 的分析功能 |

阶段 1 与阶段 0 的后半可以并行；阶段 3 与阶段 4 互不依赖，先做哪个取决于第 6 节的回答。

### 3.1 阶段 1 的拆分（可直接开 issue）

全部是能力建设，标签 `核心`；每项被一台 `sb-*` 设想仪表实际使用（D50，块覆盖测试）。

| 编号 | 内容 | 依赖 | 完成条件 |
| --- | --- | --- | --- |
| F1-1 | 通用 ADC 的非理想：有效位数随输入频率的曲线（声明若干点，按频率插值为附加噪声）、积分非线性（声明多项式系数，在量化之前施加） | — | 未声明时现有型号的回复逐位不变；对单音输入，由采集数据算出的信纳比与声明的曲线在写明的容差内一致，容差的来源写明 |
| F1-2 | 交织失配：子 ADC 的增益、偏置、时延失配，产生位置可预先算出的杂散 | F1-1 | 杂散的频率与幅度和解析式一致；失配为 0 时回复不变 |
| F1-3 | 示波器数学通道：加、减、乘、FFT（复用 S10 的窗与 FFT 纯函数），按采样流实现 | #955 | 一台 `sb-*` 示波器的 FFT 迹线，对已知单音的峰值频率与幅度和窗的解析修正一致；超出 FFT 上限时拒绝 |
| F1-4 | 频谱仪多个独立标记与噪声标记 | — | 噪声标记的读数与声明的噪声底、检波方式的修正一致 |
| F1-5 | 带功率类测量：通道功率、邻道功率比、占用带宽，作为迹线之上的纯函数 | F1-4 | 对已知多音输入，结果与 `refcalc/` 的独立计算一致（architecture.md 10.2） |
| F1-6 | 零扫宽：固定调谐，迹线是包络随虚拟时间的变化 | #954 | 调幅信号的包络周期与调制频率一致；RBW 小于调制频率时包络被滤平 |
| F1-7 | 设想仪表 `sb-dso-o1`、`sb-sa-a1`：按第 1 节的 O1、A1 填参数，写一份走完上述功能的验收脚本 | F1-1 – F1-6 | 脚本在 `acceptance/` 下通过；用不到的能力不写进定义 |

### 3.2 阶段 2 之前要先定的设计

阶段 2 改的是信号表示，影响文件格式与全部读信号的组件，属于要写决策的范围（修改 D67，不新增条目）。先写设计，再拆 issue。设计要回答：

1. **时域信号源怎样进入解析的模拟域。** 方向（positioning-review.md 8.2 已给出）：信号描述增加“有限长记录”的叶子，经线性网络时用频域方法（记录的 FFT 乘传递函数）。要定：记录长度的上限与拒绝规则；它与稳态谱线叠加时的求值；非线性器件怎样处理。
2. **带通信号怎样表示。** 方向：叶子为“中心频率 + 复包络”，复包络是周期的或有限长的采样序列；线性网络只在包络带宽内求值。要定：包络采样率与带宽的关系；经混频器后的中心频率平移；与现有调制（AM/FM/PM 展开为谱线）的关系，哪些保留解析。
3. **保住三条不变量。** 同一时刻两次读取相同；被动读取不改变仿真（D55）；超出能力时拒绝而不是截断。
4. **不做什么。** 不做电路级瞬态求解（非线性器件的时域积分）；这条边界在 D67 的“备选一”里已经划过，设计里重申。

完成条件：设计文档经产品负责人确认；现有全部金标准在新表示下回复不变。

### 3.3 阶段 3 的判断方法

不预先决定用 Rust 重写哪一部分。先做两件事，再按结果拆：

- 给 `sb-dso-o1` 的 1 Gpts 采集与 `sb-sa-a1` 的 160 MHz IQ 采集各写一个基准测试，记录耗时与内存的分布；
- 把“一帧整块计算”改为“按块计算、逐块交付”，上限从“帧的点数”改为“同时在内存里的点数”。只有这一步之后仍然慢的内核，才改用编译实现（D19 的边界）。

## 5. 不做的

- **电路级瞬态仿真**（SPICE 的范围）与 HDL 仿真。
- **完整的通信标准解调与协议栈**（5G、Wi-Fi 的全套测量应用）、协议解码、眼图与抖动分解：算法团队已有模型的，经算法托管接入（product-plan.md P4-1）；平台只提供 IQ 与波形数据、测量结果的命令入口。
- **光与太赫兹器件的物理**：扩频头只按“变频损耗、噪声系数、频率平移”的功能块建模。
- **按厂商的真实电路建模**：内部结构是功能框图级（signal-chain.md 的约束）。

## 6. 需要产品负责人回答的

1. 第 1 节的六档里，公司五年内会做的是哪几档？只做 O1 与 A1 的话，阶段 3、4 可以不做。
2. 示波器与频谱仪哪个优先？阶段 1 的两半（F1-1 – F1-3 与 F1-4 – F1-6）互不依赖。
3. 阶段 2 改信号表示，工作量与信号链第一版相当。是在试点仪表（product-plan.md H1）定下来之后再开始，还是现在就写设计？建议：设计现在写，实现等阶段 1 完成。
4. 设想仪表 `sb-dso-o1`、`sb-sa-a1` 的规格用第 1 节的数字是否可以，还是先向内部的仪表工程师问一轮？

## 7. 风险

- **设想不准。** 第 1 节是推断。对策：阶段按能力划分而不是按型号，规格变了改的是第 1 节的数字与阶段 3、4 的取舍，阶段 1、2 的内容基本不变。
- **没有人验收。** 这些能力的验收者应是仪表工程师（D11）；在此之前，每项的完成条件都写成与解析式或独立计算比对（architecture.md 10.2），不靠“看起来像”。
- **与近期计划争资源。** 阶段 0 优先；阶段 1 只在阶段 0 的核心项排开之后并行。
- **做成没人用的通用框架。** 沿用 signal-chain.md 9.2 的对策：每个新块必须被一台设想仪表的验收脚本实际使用。
