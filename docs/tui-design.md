## 0. 参考视频的观察

博客中的短视频 `twelve-find-the-trip.mp4`（7 秒，1600×1192）演示“在 12 台仪表中找到跳闸的那台”，共三步，每步屏幕底部有一条字幕和对应按键：

| 时刻 | 字幕 / 按键 | 画面 |
| --- | --- | --- |
| 0–1.5 s | Twelve simulated instruments; one card is red | 总览：3 列 × 4 行卡片，下方是 SCPI LOG（“no records yet”，右下角“0 records”）。SIM-PSU-4 卡片中 `OVP` 与 `ERRORS: 1  324` 是红色 |
| 1.5–2.5 s | Key 4 moves the focus to the red card · `key ▸ 4` | 焦点移到第 4 张卡片，**焦点边框为琥珀色**；红色只用在出问题的那几个字上，卡片边框本身不变红 |
| 2.5–4 s | Enter opens it: a 5 V setpoint against a 4 V OVP level · `key ▸ enter` | 仪表屏幕：顶部身份框（ID、VISA 地址、PROFILE、ERRORS）；每个通道一个框，分 STATUS / VOLTAGE / CURRENT 三列“标签: 值”，下面一排按钮（OUTPUT、OCP、V SET、OVP、I SET、OCP SET），焦点按钮反白；通道右侧是 WIRING（端口、网络）与 LOAD（所接负载，“not wired”）两个小框；底部仍是 SCPI LOG。字幕把 SET 5.000 V 与 OVP 4.000 V 两个值框出来，说明原因 |
| 4–7 s | The error query returns 324 and empties the queue · `sim-psu-4 ▸ SYSTem:ERRor?` | 另一个客户端发出 `SYSTem:ERRor?`，屏幕实时更新：日志出现一行 `00:00:04.200  SYSTem:ERRor?  → 324,"Overvoltage protection tripped"`（命令与回复在同一行），计数变为“1 records”，ERRORS 变为 0；TRIP 仍为 OVP（读错误队列不复位保护） |

顶栏居中是“edgesim — 测试台名 | 当前屏幕”（面包屑），右侧是 `scaled t = 1.067 s`（时钟模式 + 时间，持续走动）；底栏列出当前屏幕的按键（`⏎ Open  space Power  f Fault  q Quit  a Advance 1 s  n Nets  l Log`，仪表屏幕换成 `esc Back  + - Step  e Edit  / Search  t Tree  L Latent …`）。界面是黑底单色、等宽字体，标签灰、数值白且加粗，颜色只有红（故障）与琥珀（焦点、强调）。

从视频得到的设计要点（已写入下文）：

1. **一眼找到问题**：总览卡片的信息密度高（每通道一行），问题只用红字标出具体的项（模式槽里写 `OVP`，错误数后跟最近的错误码），不靠整块变色；
2. **数字键直达 + Enter 打开**，两次按键从总览到原因；
3. **原因就在屏幕上**：仪表屏幕把“设定值”和“限值”并排放在同一列，配合限值字段一眼看出 5 V > 4 V；
4. **SCPI 日志常驻底部**，命令与回复同一行，外部脚本的操作实时出现，屏幕上的状态（错误计数）跟着变；
5. **连线与负载就在仪表旁边**，不用切到网络屏幕；
6. 视频本身是**脚本化录制**的：按键序列 + 字幕 + 高亮框，同一脚本生成同一视频（见第 6 节）。

## 1. 定位

D18 定下“第一个界面是 Web Bench，TUI 以后作为补充”；architecture.md 8.1 比较过两者。TUI 不是第二个 Web Bench，而是**在终端里观察和操作运行中的测试台**：

| 场景 | 为什么用 TUI |
| --- | --- |
| 远程服务器、实验室工控机、CI 机器上调试 | 只有 SSH，没有浏览器，也不想做端口转发 |
| 一边在终端跑脚本 / pytest，一边看仪表状态 | 与脚本在同一个终端窗口里分屏（tmux），不切到浏览器 |
| 快速确认“测试台在不在跑、信号到没到、哪台仪表报错” | 启动快、全键盘、信息密度高 |
| 文档与 CI 中可复现的截图 | 同一测试台 + 同一操作脚本 → 逐字节相同的 SVG |

**做**：测试台总览、仪表面板与屏幕、网络电平与探针、通信记录、故障注入、时钟控制、运行记录列表。

**不做**（交给 Web Bench，TUI 中给出“在浏览器中打开”的链接）：画布编辑与连线、版本历史与差异审阅、仪表定义编辑、仪表内部组件图、波形的精细测量（光标、缩放）。TUI 能看波形的大概，不替代示波器屏幕。

### 1.1 差异化：从“看到红字”到“知道为什么、谁造成、何时”

参考视频里，原因（5 V 设定对 4 V OVP）是录制时人工加的字幕与高亮框，TUI 自己没有说出来；读完错误队列后，跳闸的痕迹也从屏幕上消失了。SimuBench 已有的能力可以让 TUI 自己给出这些信息，这是 TUI 不与 EdgeSim 逐项对齐、而要做得更好的方向：

| 能力 | 依据（已有） | TUI 中的表现 |
| --- | --- | --- |
| **原因由引擎给出** | 因果解释（D37）、0 V 溯源（`engine/silence.py`） | 在红字（跳闸、过载、错误码）或读数上按 `?`：显示因果链，例如“跳闸：设定 5.000 V 超过 OVP 4.000 V · 00:00:04.230 · 脚本 `127.0.0.1:53122` 发出 `:SOURce:VOLTage 5`” |
| **证据不随一次查询消失** | 运行记录（D36） | 仪表屏幕的错误历史：出现过的每个错误、时刻、引起它的命令与来源；已被读走的错误灰显而不是消失；Enter 跳到通信记录中的那一行 |
| **故障的来源分开** | 故障预设与注入（D27） | 标明“预设故障（测试台文件）”“注入故障（终端 / 界面 / Agent）”还是“命令导致” |
| **命令为什么没被执行** | 定义、覆盖表（D42）、`unknown_commands`、`builtins`（D45） | 按命令的实际来源给出提示，见下表 |
| **所有客户端同一会话，每行标来源** | D9、D32 | 通信记录每行标“脚本 / Agent / 界面 / 终端”；远程与本地的切换与真机一致 |
| **真实值** | D9 的真实值开关 | 开启时读数旁以紫色显示真实值，定标软件直接对照读数与真值之差 |
| **演示即证据** | 第 6 节 | 演示脚本同时产生运行记录，截图中的每个状态都能在记录中复核 |

#### 命令没被执行时的提示

提示按命令的来源区分，不能一律引用手册：只有带 `reference` 的真实型号有手册可引；工程师自己组装的定义（如 `examples/lowfreq-cal/`）没有手册。

| 情况 | 依据 | 提示 |
| --- | --- | --- |
| 真实型号，手册有这条命令，覆盖表标为“未实现” | 覆盖表 `<id>.coverage.yaml` | `未建模 · <手册名称与版本> <章节> · 仿真尚未实现`：模型缺口，不是脚本的问题 |
| 真实型号，手册中没有这条命令 | 覆盖表中查不到 | `手册中没有这条命令 · 真机同样回复 -113`：多半是脚本写错，附命令树中最接近的命令 |
| 自建定义（无 `reference`），定义中没有这条命令 | 定义文件 | `定义 <文件> 中没有这条命令`：可能是脚本写错，也可能是定义没写全；附最接近的命令与“在 Web 中打开定义” |
| 自建定义，`unknown_commands: ignore` | 定义文件 | `已忽略 · 定义设为 ignore` |
| 型号限定了 `builtins`，脚本发了其余公共命令（如 `*CLS`） | 定义的 `builtins` | `这个型号不回答 *CLS · 定义的 builtins` |
| 命令存在，参数超出范围或类型不对 | 定义中的参数声明 | 照常显示 SCPI 错误，并写出定义给出的范围 |

只有真实型号能确定地区分“模型没做”与“脚本写错”（手册是第三方依据）；自建定义没有外部依据，TUI 只如实说“定义中没有”，给出最接近的命令，由工程师判断，不替他下结论。

**需要的引擎改动**：现在 `engine/instrument.py` 对真实型号定义中没有的命令一律记为 `reason: not_modeled`（回复 `-113,"…;not modeled by SimuBench"`），不区分“手册有、未实现”与“手册没有”；自建定义的 `-113` 没有分类，`ignore` 记为 `reason: unknown_command`。需要在错误事件中给出完整分类（`not_modeled`、`not_in_reference`、`not_in_definition`、`ignored`、`builtin_excluded`、`bad_parameter`），真实型号运行时按覆盖表查找，并附上最接近的命令；事件 schema 随之重新生成。手册中没有的命令是否还应回复 `not modeled by SimuBench`（真机只回复 `-113,"Undefined header"`）另开 issue 讨论，不在 TUI 范围内。

## 2. 架构：TUI 是服务的一个客户端

```
              ┌──────────────── simubench serve（或 mcp）────────────────┐
 PyVISA 脚本 ─┤ SCPI 网络仪表 / HiSLIP                                    │
 pytest      ─┤                                                          │
 Agent (MCP) ─┤ MCP          引擎：会话、动作队列、运行记录（D9 并发串行） │
 浏览器      ─┤ HTTP + WebSocket ──┐                                      │
 TUI         ─┤ HTTP + WebSocket ──┘  同一套 /api 接口（D7、D21）          │
              └──────────────────────────────────────────────────────────┘
```

- **只走 HTTP/WebSocket 接口**，与 Web Bench 用同一批端点（`/api/sessions/...`、`/levels`、`/screen`、`/panel`、`/faults`、`/clock`、WebSocket `events`），不直接调用引擎。理由：
  1. 远程状态（D32、#121）、令牌（D43）、Host/Origin 校验、危险确认的语义与 Web 完全一致，不需要第二份实现；
  2. 同一个会话可被脚本、Web、Agent、TUI 同时观察（D9），TUI 只是又一个观察者；
  3. 接口模型是 Python 中的 Pydantic（D21 单一来源），TUI 直接复用 `simubench.models.api`，不需要生成客户端，接口改动由类型检查与测试发现。
- **两种启动方式**，内部是同一条路径：
  - `simubench tui <bench.yaml>`：在本进程后台线程中启动服务（只监听 127.0.0.1、端口自动分配，与 `simubench serve` 相同的参数：`--hislip-port`、`--idle` 等），打开会话并连上它；退出 TUI 即关闭服务。SCPI 端口照常监听，另一个终端的脚本可以直接连。
  - `simubench tui --attach [http://127.0.0.1:8000] [--session <sid>]`：连接已运行的 `serve` / `mcp` 服务；有多个会话时先让用户选。
- **来源标记**：TUI 发出的操作在运行记录与事件中标为来源“终端”（与“界面”“Agent”并列），回放与审阅时能分辨是谁动的手。现在服务端把 HTTP 接口的操作一律记为 `client="ui"`（`server/manager.py`），需要让请求带上客户端类型（例如请求头 `X-SimuBench-Client: tui`，缺省仍为 `ui`），这是接口改动，走 schema 生成。
- **接口补充**：示波器屏幕（`/screen`）现在固定返回 400 点，TUI 需要按终端点阵宽度请求（增加可选的 `points` 参数，Web 也可用它按画布宽度取点）；`/levels`、`/nets/{net}/waveform` 已有点数参数。除这两处外不需要新端点。
- **技术栈**：[Textual](https://textual.textualize.io/)（Python，Windows Terminal 与 Linux 终端都可用，支持鼠标、CJK 双宽字符、SVG 截图、无头测试 `Pilot`）。作为可选依赖 `simubench[tui]`（与 `simubench[mcp]` 一致），不进入核心依赖；未安装时 `simubench tui` 提示安装命令。HTTP 用 `httpx`，WebSocket 用 `websockets`（`uvicorn[standard]` 已带）。

## 3. 界面结构

所有屏幕共用顶栏与底栏：

```
┌ SimuBench — siglent_scope_rc | 总览 ──── ● 等待命令  命令时钟  t = 00:00:04.200 ─┐   顶栏
│                                                                               │
│                         当前屏幕（总览 / 仪表 / 网络 / 通信 …）                  │
│                                                                               │
└ n 网络  l 通信  f 故障  a 推进  ? 帮助  q 退出 ─────────── 远程：scope ← 1 个客户端 ┘  底栏
```

- **顶栏**：“SimuBench — 测试台名 | 当前屏幕”的面包屑、运行状态（D44 的“等待命令 / 执行命令 / 时钟走动”，文字 + 颜色）、时钟模式、虚拟时间；断开时显示“已断开，只读，正在重连”。
- **底栏**：当前屏幕可用的按键（随焦点变化，Textual `Footer`）；右侧显示远程状态（哪台仪表被哪个客户端占用，D32）。

```
└──────────────────────────────┘└──────────────────────────────┘└──────────────────────────┘
```

- 每台仪表与元件一张卡片，按测试台文件的顺序、自适应列数排列，标题前是数字键编号。卡片内容由**与 Web 相同的数据**生成：`*IDN?` 身份、每通道一行的摘要（模式 / 输出开关 / 设定 / 读数）、连线（端口 → 网络，未接为 `—`）、错误队列计数与最近的错误码（`GET /instruments/{name}`）；示波器通道行带盲文字符缩略图（`/levels` 的 `wave`，D44）；元件显示端口所连网络与电平。DUT 带标记。
- **颜色只标在出问题的那几个字上**（跳闸、过载、限值、错误数与错误码为红字），卡片边框不因状态变色；**焦点卡片用琥珀色边框**。状态始终同时有文字（ui-design.md 4.2）。
- 下方是常驻的通信记录：**命令与回复同一行**（`→` 后为回复，写入无回复为 `·`），右上角为条数；外部脚本、Agent、Web 的操作实时出现。`l` 展开为全屏。

```
│ 00:00:04.230  :SOURce:VOLTage 5      ·                                              │

```

按仪表的面板生成，与 Web 共用 `library/panels.py` 的 `effective_panel`（类别模板 + 通用布局，D1）。布局参照视频：

- **身份框**：`*IDN?`、资源地址（SOCKET / HiSLIP，脚本可直接复制）、型号定义、错误计数与最近错误码；
- **每通道一个框**，按量分列（状态 / 电压 / 电流，或示波器的垂直 / 水平 / 触发），每列是“标签: 值”，**设定值与对应限值放在同一列相邻行**，跳闸时一眼看出原因；框底是一排按钮，焦点按钮反白；
- **通道右侧是连线与负载**：端口 → 网络，以及网络另一端是什么（元件及其主要参数，或另一台仪表的端口）；未接线写“未接线”；
- **底部是只含本仪表的通信记录**；
- **读数**（D32 只读读数接口，不产生通信记录、不推进时间）：等宽数字 + 单位，按仪表分辨率取有效位；
- **控件**：开关、枚举、数值；Enter / `e` 编辑，`+` `-` 按步进调整，Space 切换开关；经 `POST /configure`，被远程占用时提示并提供“本地（LOCAL）”（D32）；
- **面板操作**：运行 / 停止 / 单次等软键（`display.actions`，`POST /panel`）；
- **SCPI 控制台**：`:` 打开单行输入，查询结果就地显示（`POST /scpi`，与 Web 控制台相同，不取走脚本的回复）；
- **危险操作**：打开输出等需二次确认的命令弹出确认框，写明命令、仪表与影响（ui-design.md 第 5 节）。

#### 示波器、频谱仪等屏幕

用盲文字符（每个字符 2×4 点）画迹线：80 列终端约 160×(行数×4) 点。与 Web 一样只取屏幕需要的点数（architecture.md 8.3），TUI 请求时传入**点阵宽度**（第 2 节的 `points` 参数），不接收全部采样。通道颜色与 Web 相同（CH1 黄、CH2 青、CH3 品红、CH4 蓝）；终端不支持真彩色时退回 16 色并在图例中写通道名。屏幕下方列出档位、触发与自动测量。`r` 运行 / 停止，`s` 单次，与面板操作相同。

### 3.3 网络（`n`）

左侧是网络列表（名称、驱动端、直流 / 有效值 / 峰值、是否有信号，来自 `/levels`）；右侧是所选网络的波形（`/nets/{net}/waveform`）与探针结果。`w` 切换波形，`?` 请求“为什么是这个值”（D37 因果解释；0 V 时沿电路向上游追溯原因，`engine/silence.py`）。Enter 跳到驱动这条网络的仪表屏幕。

### 3.4 通信（`l`）

全屏通信记录：时间（虚拟 / 真实可切换）、仪表、方向、命令或回复、字节数、来源。`/` 过滤（按仪表、文字、只看错误），二进制块显示摘要，Enter 展开十六进制。WebSocket 事件流增量追加；超过一定条数只保留可见窗口附近的行（与 Web 的虚拟列表一致）。

### 3.5 故障（`f`）

在当前仪表或网络上注入故障：先选类型（超时、断连、乱码、延迟、忙、错误码、保护跳闸、参数漂移，D27），再填参数与持续时间；列出生效中的故障，可撤销。经 `/faults` 接口，写入运行记录。

### 3.6 运行记录（`R`）

列出 `/api/runs`，显示时间、测试台、命令数、结果；Enter 查看摘要，`p` 回放并报告第一处不同（`/runs/{id}/replay`）。时间线与逐条对比留在 Web。

## 4. 按键

| 范围 | 按键 |
| --- | --- |
| 任意屏幕 | `n` 网络 · `l` 通信 · `f` 故障 · `R` 运行记录 · `a` 推进虚拟时钟（步进时钟下按设定步长；命令时钟下弹出时长输入） · `Ctrl+P` 命令面板 · `?` 帮助 · `Esc` 返回 · `q` 退出 |
| 总览 | 方向键 / Tab 在卡片间移动 · `1`–`9` 跳到第 n 张卡片 · Enter 打开 · Space 切换所选仪表的主输出（需确认） |
| 仪表屏幕 | Tab / 方向键在控件间移动 · Enter / `e` 编辑 · `+` `-` 步进 · Space 切换 · `:` SCPI 控制台 · `L` 本地（从脚本接管） |
| 示波器 / 频谱仪 | `r` 运行 / 停止 · `s` 单次 · `c` 切换显示的通道 |
| 网络 | ↑↓ 选择 · Enter 打开驱动端 · `w` 波形 · `?` 为什么是这个值 |

- 键位以 EdgeSim 控制台为参照，使从那边过来的用户不用重新学；与 Web Bench 的快捷键冲突时以 Web 为准（例如命令面板）。
- 所有操作都能通过命令面板搜索执行；鼠标可用但不是必需。

## 5. 视觉与文案

- **配色**：以终端默认前景 / 背景为底的单色界面；颜色只用于通道（与 Web 相同）与状态（绿 / 琥珀 / 红 / 灰）；仿真专属信息（真实值、保真度标注 ≈）用紫色。浅色与深色终端都可读；`NO_COLOR` 环境变量下完全不用颜色，状态全靠文字。
- **数值**：工程单位与 SI 前缀，数字右对齐、等宽（终端天然等宽），与 Web 相同的格式化函数（服务端 `_eng` 一类的实现抽到共用模块）。
- **语言**：中文为主、英文为辅（D23），`--lang zh|en`，默认跟随 `LANG`。术语按 glossary.md。文本外置在 Python 侧的 `tui/i18n` 中；与 Web 重复的词条（状态、按钮、错误提示）以 `web/src/i18n` 为准，由检查脚本比对，避免两边措辞漂移。
- **宽度**：最小 80×24；更窄时提示放大窗口，不做挤压布局。CJK 字符按双宽计算（Textual 内置）。

## 6. 可复现截图与演示录制

`simubench tui <bench.yaml> --script <steps.yaml> --out <dir>`：无头运行，按步骤文件执行，输出 SVG 截图，或一段带字幕的演示（参考视频就是这样做的）。

```yaml
# docs/tui/find-the-trip.steps.yaml
size: [100, 34]
steps:
  - caption: 测试台上有一台 SMU 跳闸了
    wait: 1.5s
  - key: "1"
    caption: 数字键把焦点移到这张卡片
  - key: enter
    caption: 打开它：设定 5 V，电流限值 1.05 mA
    highlight: [ch1.voltage.set, ch1.current.limit]
  - scpi: { instrument: smu, command: ":SYSTem:ERRor?" }   # 以另一个客户端发出，与脚本相同
    caption: 读错误队列，返回 -5000 并清空
    highlight: [identity.errors, log.last]
  - screenshot: find-the-trip
```

- 步骤：`key`（按键）、`scpi`（以外部客户端发命令，验证“脚本操作实时出现在屏幕上”）、`advance`（推进虚拟时间）、`wait`（演示中停留的时长，不推进虚拟时间）、`caption`（底部字幕，右侧自动写出按键或命令，如 `key ▸ enter`）、`highlight`（给控件加琥珀色框）、`screenshot`；
- 输出：每个 `screenshot` 一张 SVG；`--record` 时按 `wait` 输出逐帧 SVG 与 asciinema `.cast`，需要视频时由文档构建脚本转成 MP4 / GIF（不进入运行时依赖）；
- 使用 `idle: off` 与固定种子（D47），虚拟时间只由步骤推进，同一测试台 + 同一步骤 → 逐字节相同的 SVG；
- 文档中的 TUI 截图由它生成，CI 重新生成并比较（与 Web 的视觉回归同理）；
- 截图只是某一时刻的画面，不是测试结果——判定以运行记录为准（D36）。

## 7. 状态与错误

与 Web 的“完整的状态”要求一致（roadmap.md 界面质量标准）：

| 状态 | 表现 |
| --- | --- |
| 连接中 / 加载 | 顶栏“正在连接 …”，屏幕显示占位而不是空白 |
| 服务断开 | 顶栏红色“已断开”，界面只读，后台按退避重连，恢复后重新拉取状态并补齐事件（WebSocket 的 backlog） |
| 令牌无效 | 提示 `--token` 或 `SIMUBENCH_TOKEN`，不反复重试 |
| 会话不存在 / 被关闭 | 回到会话选择，说明原因 |
| 仪表被远程占用 | 控件只读，底栏写明占用的客户端，`L` 接管（D32） |
| 测试台文件被修改（D25） | 顶栏提示“文件已改，可重建”，重建需确认（有脚本连着时会断开它们） |
| 测试台无法构建 | 列出校验诊断（错误码、位置、建议），提示在 Web 或编辑器中修改 |

## 8. 测试

- **单元与交互**：Textual `Pilot` 驱动，服务端用测试中的 FastAPI 应用（与现有 `tests` 的方式相同）；覆盖每个屏幕的按键路径、远程状态、断线重连、危险确认。
- **快照**：`pytest-textual-snapshot` 对每个屏幕在中英文、80 列与 120 列下各一张 SVG 快照，进入 PR 的快速检查（纯 Python，Ubuntu 上运行）。
- **跨平台**：Windows 上的 TUI 测试随 `main` 上的 Windows 任务运行（D20）。
- **端到端**：一个 PyVISA 脚本驱动信号源，TUI 中的读数随之变化（博客中“脚本与控制台并排”的场景），验证 TUI 与脚本共用同一会话。
- `scripts/check.sh` 增加 i18n 词条比对。

## 10. 待确认（确认后写入 decisions.md）

1. **TUI 只通过 HTTP/WebSocket 接口访问引擎**（第 2 节）。另一条路是进程内直接调用引擎（少一层、启动更快），但远程状态、确认与来源标记要再实现一遍，且无法与 Web / 脚本共用会话。建议前者。
2. **Textual 作为可选依赖 `simubench[tui]`**。替代方案：urwid、prompt_toolkit（更底层，截图与无头测试要自己做），或 Rust 的 ratatui（与 D19 的 Python 起步不符）。建议 Textual。
3. **TUI 的范围**：只观察与操作运行中的测试台，不做编辑（第 1 节）。是否需要在 TUI 中做最基本的编辑（例如改一个元件参数）？建议不做，保持“文件是唯一来源”（D25）只有画布、MCP 与编辑器三个入口。
4. **事件来源增加“终端”**（请求头 `X-SimuBench-Client`）：会改变接口与运行记录的 schema（D21 生成物）。是否接受，还是 TUI 沿用“界面”？建议增加，审阅运行记录时能分辨操作来自哪里。
5. **错误事件的完整分类**（第 1.1 节）：改变事件 schema，Web 的通信记录也可用同一分类。是否接受？建议接受，作为 T2 的前置 `核心` issue。
6. **D18 / architecture.md 8.1 的更新**：确认后把“TUI 以后作为补充”改为指向本文。
