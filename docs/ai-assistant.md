# Web AI 助手：设计草案

状态：**草案**。需求与框架选型（第 10 节）已与产品负责人逐项对齐；本文把与产品负责人对齐的需求整理成设计，确认后再拆成 `核心` issue（见第 9 节），并把其中跨功能的选择写入 `decisions.md`（现在不写）。

## 1. 目标

在 Web Bench 里用**对话**完成两件事，用户不需要看懂 YAML：

1. **搭建 bench**：选型号、放入 bench、连线、设置、启动。
2. **定制化仪表**：改 bench 里仪表的实例设置；把改好的仪表保存成自己的模板。

LLM 由用户配置，连接私有化部署的服务。

**不做**：Web 端从手册生成新仪表（不上传手册）；bench 的“模块”（用复制整个 bench 代替）；AI 删除 bench 文件或定义文件。

## 2. 已对齐的需求

| 项 | 结论 |
| --- | --- |
| LLM 协议 | OpenAI 兼容（`/v1/chat/completions`）与 Anthropic Messages 兼容（`/v1/messages`）都支持，配置里切换；要求模型支持 tool calling |
| LLM 配置 | 服务端配置文件或环境变量提供默认值；Web 设置页可覆盖；谁能改沿用现有 Web 权限模型（D43 令牌）；API key 只写不读，界面只显示“已设置” |
| 执行策略 | AI **直接实施**，不做预览确认 |
| 兜底 | ① 每轮改动后用自然语言总结“改了什么”；② 改完自动跑校验，失败则自修复；③ “恢复到上一轮之前”按钮 |
| 运行中修改 | bench 运行中 AI 只能调参数；改结构（连线、增删仪表）要求先停止，AI 先在对话里说明并征得同意再停止 |
| 删除权限 | 可删仪表和连线；不可删 bench 文件、定义文件 |
| 界面 | 右侧可收起的对话面板；历史存服务端工作区，与 bench 绑定，换设备或刷新后仍在 |

## 3. 定制化

### 3.1 两层对象

- **内置型号**：只读，AI 不改。
- **bench 里的仪表实例**：AI 直接改。能改的就是现有编辑操作覆盖的实例级设置：初始状态、参数、地址、标识、个体偏差、附件、标签、位置。换型号用已有的 `replace_instrument`（`engine/edit.py`，Web 检查器里已有下拉）。

### 3.2 保存为自己的模板

- 模板是**完全独立的定义**（`simubench.instrument/1`），**不再 `extends` 内置型号**：保存时把继承链展开成完整定义，之后内置型号怎么变都不影响它。
- 与已有的“复制为我的仪表”（`DefinitionFiles.copy_of`，生成 `my-<id>` 并 `extends` 父型号，D59）的差别：已有机制是活引用，父型号改名、删除，或父型号列表新增条目时，子定义会加载失败或悄悄变旧。独立快照没有这个问题。代价是拿不到内置型号后续的修正，用户需要重新保存。
- 文件格式升级（`/1` → `/2`）由 `library/migrate.py` 的迁移链处理，模板与内置型号走同一条链，不受影响。
- 这意味着要改 D59 的“复制”行为，或新增一个“展开成独立定义”的入口（见第 8 节待办）。
- **实例设置如何进入模板（已对齐一部分）**：初始状态折进模板作为默认值；`idn/serial/firmware` 作为模板的标识；**地址不进模板**（定义模型没有地址字段，地址是 bench 实例的设置，加字段会改文件格式）；用户要的“只需拿到可用地址”由平台在新增仪表时自动分配空闲地址满足，冲突不用用户解决；**个体偏差不带**，偏差的定义属于模板，抽出的值留在 bench，在新 bench 里按种子重新抽取。**保存时只问名称**：id 由平台按名称生成并防重，厂商、型号沿用实例当前的标识，要改再在对话里说。**保存后 bench 里这台自动改指向新模板**（`replace_instrument`，名称、连线、位置保留）。

### 3.3 模板的可改范围：最大

标识与默认值、通道数、量程表、端口、**SCPI 命令与回包、错误码**。理由：产品主打“自己造”，且内置型号可能有 SCPI 错误，用户要能自己纠正。

守住“拒绝猜测”原则（见 `codebase-map` 的原则）：

- AI 改命令与回包前，必须由用户给出命令格式和回包示例；信息不足就**先追问，不猜**。
- 改完自动跑 `validate_definition`、覆盖与用例，并用 `try_definition` 真实发一遍命令，把“发了什么、回了什么”用自然语言告诉用户确认。
- 内置型号的 SCPI 错误只在用户自己的模板里修，不回写内置库；是否引导用户提 bug issue 见第 8 节。

### 3.4 复制 bench

bench 不做模块。需要重复使用一组仪表加接线时，**复制整个 bench**（仪表、连线、设置全部带上），在新 bench 上继续改。这是 AI 的一个工具，也是 Web 的一个普通操作。**现在没有通用的复制 bench**：只有 `BenchFiles.create_hello` 复制随包的 Hello World，需要新增。

## 4. 架构

```text
Web 对话面板 ──HTTP/SSE──▶ /api/assistant/*  ──▶ 对话循环 ──▶ LLM 适配层 ──▶ 私有 LLM
                                    │                │
                                    │                └─ 工具集（复用 mcp_server 的实现）
                                    └─ 对话历史、快照（工作区 .simubench/）
```

- **对话循环**在服务端：把用户消息和工具定义发给 LLM，执行它返回的工具调用，把结果回给 LLM，直到得到最终回答。API key 只在服务端，不下发浏览器。
- **LLM 适配层**：统一接口，两个实现（OpenAI 兼容、Anthropic 兼容），负责消息格式、工具定义格式、流式输出的差异。配置项：协议类型、`base_url`、`model`、`api_key`、超时。
- **工具集**：复用 `mcp_server.py` 里已有的工具所依赖的同一批服务（`BenchFiles`、`DefinitionFiles`、`engine/edit.py`），不另写一套。只暴露需要的子集：

  | 目的 | 现有能力 |
  | --- | --- |
  | 了解有什么 | `list_catalog`、`list_components`、`get_definition`、`list_benches`、`read_bench` |
  | 搭 bench | `create_bench`、`edit_bench`（add / connect / set_state / replace_instrument …）、`validate_bench` |
  | 启动与观察 | `start_session`、`stop_session`、`describe_session`、`get_instrument_state` |
  | 定制模板 | `read_definition`、`edit_definition`、`validate_definition`、`try_definition`、`run_cases` |
  | 新增 | 复制 bench（现无）、保存为独立模板（展开继承）、定义的版本恢复（现无）、恢复到上一轮之前 |

  不暴露：删除 bench 或定义文件、仿真控制（故障注入、读真值，受 `--allow-control` 管）、危险 SCPI 命令（需 `confirm=true`，沿用 MCP 的规则）。
- **工具权限由服务端强制**，不靠提示词：运行中改结构、删文件等规则写在工具实现里，LLM 无论说什么都越不过去。
- **每轮上限**：工具调用次数和自修复次数有上限（参照 MCP 限频规则）；到上限就停下，用自然语言告诉用户失败原因。
- **并发**：用户在画布上手动编辑的同时 AI 也在改，沿用现有的 sha256 乐观并发（`Conflict`），冲突时让 AI 重新读取再改。

## 5. 恢复到上一轮之前

现有版本历史（D35）已经记录每次写入的来源（`ui`、`agent`、`external`、`restore`）。bench 有 `BenchFiles.versions/restore`（`POST /api/benches/restore`）；**定义只有 `DefinitionFiles.versions`，没有恢复**，要补。

- 每轮对话开始时记下涉及文件的当前版本号；“恢复到上一轮之前”就是把这些文件恢复回那个版本。一轮里 AI 改了哪些文件，由对话循环按文件记录。
- 恢复本身也是一次写入，记入历史，不丢信息。
- **服务端现在没有任何删除文件的路径**，要新增“用户发起的删除”（仅限本轮新建的文件，不开放给 AI 工具），并在 `security.md` 文件写入一行补充。
- 恢复顺序：先恢复 bench（不再引用本轮新建的模板），再删模板，避免悬空引用。
- **本轮新建的文件**（复制出的 bench、新模板）没有“之前的版本”：恢复时**一并删除**。删除由用户点按钮触发，不是 AI 删除，与“AI 不能删文件”不冲突；按钮上要先写明会删哪些文件。
- **会话**不属于文件：恢复只回退文件，**不动会话**。若要恢复的文件正被一个运行中的会话使用，先提示“需要先停止”，用户确认后停止再恢复（与“运行中不改结构”一致）。

## 6. 配置与安全

- API key 存工作区 `.simubench/` 下（已在 `.gitignore`，不会被提交），文件权限收紧。
- 配置文件：工作区 `.simubench/settings.json` 增加 `assistant` 块，或 `serve` 的命令行与环境变量（具体入口在 `service.py` 加一次，所有入口共用，见 `codebase-map`）。
- Web 设置页写入的值覆盖默认值，保存在服务端工作区；GET 接口**不返回 key**，只返回“已设置”。
- 新增的 `/api/assistant/*` 路由必须要求令牌（`test_every_api_route_needs_the_token` 会遍历全部路由）。
- 私有 LLM 地址可以是内网地址。这是服务端发出的请求，不是浏览器发的，不受 Host/Origin 检查影响；要在 `security.md` 里补一行，说明这是有意的取舍。**已定**：只允许 `http`/`https`，不允许指向本机 SimuBench 自身的端口（Web、SCPI、连接模式）；内网地址允许，因为私有化部署本来就在内网。
- 对话内容（含用户描述的仪表信息）会发给用户自己配置的 LLM，不会发给别处。

## 7. Web 界面

- 流式输出；工具调用过程显示为简短的进度行（“正在添加示波器”），不展示 JSON、不展示 YAML。
- 所有文案走 i18n（`web/src/i18n`），按 `web-ui` 技能的规则；TUI 是否同步见第 8 节。

## 10. 对话循环：框架选型调研（未定）

要解决的事：工具调用循环、两种协议（OpenAI 兼容、Anthropic 兼容）、流式输出、上下文裁剪（保留系统提示和最近几轮、截断长工具结果、不拆开一次工具调用与它的返回）。现有依赖只有 numpy、scipy、pydantic、pyyaml、pyvisa、fastapi、uvicorn；要求 Python ≥ 3.11，wheel 多平台分发（含 Windows）。

以下来自网上检索，**未在本仓库里验证**，选型前要各做一次小验证：

| 候选 | 已知 | 未验证 |
| --- | --- | --- |
| **PydanticAI** | 文档有“压缩”（compaction）：用历史处理器裁剪旧消息、清理旧工具结果，并保证工具调用与返回成对；与现有依赖 pydantic 同源 | 自定义 `base_url` 的 OpenAI 兼容与 Anthropic 兼容是否都顺畅；能否直接把 `mcp_server.py` 的工具当工具用；传递依赖体积 |

- 自定义 `base_url` 下，OpenAI 兼容与 Anthropic 兼容两种协议都能跑通工具调用和流式输出；

- 上下文裁剪按配置的模型上下文长度生效，不拆开工具调用与返回，裁剪时面板提示；
- wheel 体积、Windows 与 CI 安装时间可接受。
