# 终端控制台（TUI）界面与功能规格

状态：生效（D18）。本文是 [tui-design.md](tui-design.md) 的实现规格：每个屏幕显示什么、数据从哪个接口来、按什么规则显示、按键做什么、文案怎么写。实现按本文做，**不自行增减功能或改动接口**；本文没写到、又必须决定的地方，在 issue 中提出，由主 agent 补进本文后再做。

示意图由脚本按真实接口数据生成（示例测试台见第 1.3 节），中文按两列宽对齐；颜色无法在示意图中表示，写在每张图下面。

## 1. 约定

### 1.1 尺寸与布局

- 设计尺寸 **100 × 32**（列 × 行），所有示意图按此尺寸；最小 **80 × 24**，更小时整屏只显示一行“窗口太小：至少 80 × 24，当前 W × H”。
- 宽于 100 列时卡片列数增加、通信记录变宽；高于 32 行时通信记录变高。布局规则见各屏幕。
- 每个屏幕 = 顶栏（1 行）+ 内容 + 底栏（1 行）。顶栏与底栏为反色条，不画边框。

### 1.2 颜色与字形

只用以下语义颜色，实现中定义为 Textual 主题变量，`NO_COLOR` 时全部为默认前景色：

| 令牌 | 用途 | 深色终端 | 浅色终端 |
| --- | --- | --- | --- |
| `fg` | 数值、正文 | 默认前景，数值加粗 | 同左 |
| `muted` | 标签、单位、次要信息、已读走的错误 | 灰 | 灰 |
| `focus` | 焦点边框、高亮框、焦点按钮的底色 | 琥珀 | 深琥珀 |
| `bad` | 错误码、跳闸、受限（▲）、断开 | 红 | 深红 |
| `ok` | 运行中的状态点（●） | 绿 | 深绿 |
| `sim` | 仿真专属信息（真实值、≈ 保真度） | 紫 | 深紫 |
| `ch1`–`ch4` | 示波器通道、迹线、缩略图 | 黄、青、品红、蓝 | 同色加深 |

规则：

- **红色只标出问题的那几个字**（错误码、`▲`、`CC` 受限、`跳闸`），不把整张卡片或整行染红；卡片边框只在有焦点时变为 `focus`。
- 状态永远同时有文字（ui-design.md 4.2）：不能只靠颜色区分。
- 字形：`●` 有信号 / 运行，`○` 关，`▲` 受限，`✗` 错误回复，`→` 查询回复，`·` 写入无回复，`←` / `→` 连线方向（输入 / 输出），`—` 未接线，`…` 截断，`▸` 列表当前行。波形与缩略图用盲文点阵（U+2800–U+28FF，每字符 2 × 4 点）。

### 1.3 示意图用的示例测试台

`awg`（Siglent SDG2042X）→ `rc`（RC 低通，DUT）→ 10x 探头 → `scope`（Siglent SDS2104X Plus）；`smu`（`sb-smu-1`）HI → `r1`（1 kΩ，DUT）与 `dmm`（`sb-dmm-1`）。SMU 设定 15 V、电流限值 10 mA，因此受限于 CC（实际 9.999 V、10 mA）。数据取自 `examples/benches/siglent_scope_rc.bench.yaml` 与 `validation/benches/smu.bench.yaml` 的真实会话。验收时用这两份测试台（第 14 节）。

### 1.4 数值格式

一个函数 `fmt(value, unit, digits)`，所有屏幕共用（服务端 `library/panels.py` 的 `_eng` 抽到共用模块，Web 与 TUI 一致）：

- 工程前缀：p n µ m（无）k M G；`1000.0 HZ` → `1.000 kHz`，`0.01 A` → `10.000 mA`。
- **设定值** 5 位有效数字（`15.000 V`、`10.000 mA`、`1.0000 kHz` 截为显示宽度时可降到 4 位）；**读数** 用面板 `PanelReadout.digits`，没有时 5 位。
- 单位按状态变量的 `display_unit` → `unit` 显示；`HZ` → `Hz`，`OHM` → `Ω`，`S` → `s`。示波器档位加 `/div`。
- 枚举用 `option_labels`（如 `VOLTage` → `电压源`），没有时显示原值；布尔为“开 / 关”；`INF` 负载为“高阻”。
- 数值列右对齐，单位前一个空格。
- 时间：虚拟时间 `HH:MM:SS.mmm`（`now_ns` 取整到毫秒）；真实时间 `HH:MM:SS.mmm`（本地时区）。

### 1.5 来源名称

通信记录、错误历史与原因中，事件的 `client` 按下表显示：

| `client` | 显示 |
| --- | --- |
| `ui` | 界面 |
| `tui` | 终端（#175 新增） |
| `mcp` | Agent |
| `pyvisa` | 脚本 |
| `socket:<host>:<port>`、`hislip:…` | `脚本 :<port>`（主机为 127.0.0.1 时省略主机） |
| `replay` | 回放 |
| 故障事件的 `source: bench` | 预设 |
| 无 `client` 的事件（采集、时钟、故障生效） | 事件 |

### 1.6 数据与刷新

TUI 只调用以下接口（D18），不新增端点；括号内是本文规定的两处接口补充。

| 数据 | 接口 | 何时读取 |
| --- | --- | --- |
| 会话、仪表列表、元件、连线、网络、客户端 | `GET /api/sessions/{sid}` | 启动、重连、收到 `session` / `remote` 事件 |
| 一台仪表的状态、错误队列、面板 | `GET /api/sessions/{sid}/instruments/{name}` | 收到该仪表的 `state` / `error` / `scpi` 事件后（同一仪表 100 ms 内合并为一次） |
| 只读读数 | `GET …/instruments/{name}/readings` | 同上；墙钟模式另外每秒一次 |
| 网络电平与缩略图 | `GET /api/sessions/{sid}/levels` | 任一 `state` 事件后（200 ms 内合并） |
| 网络详情 | `GET …/nets/{net}/probe` | 网络屏幕选中时，及其后的 `state` 事件 |
| 示波器屏幕 | `GET …/instruments/{name}/screen`（**新增可选参数 `points`**） | 示波器屏幕可见时：运行中每 200 ms，停止时只在 `acquisition` / `state` 事件后 |
| 故障 | `GET` / `POST …/faults`、`DELETE …/faults/{id}` | 打开故障对话框、收到 `fault` 事件 |
| 事件流 | WebSocket `…/events` | 常连；断开后重连并以 backlog 补齐（按 `seq` 去重） |
| 时钟 | `GET …/clock`、`POST …/clock/advance` | 顶栏；墙钟模式每秒刷新显示 |
| 写操作 | `POST …/scpi`、`…/configure`、`…/panel`、`…/local` | 用户操作；请求都带**请求头 `X-SimuBench-Client: tui`**（新增） |
| 运行记录 | `GET /api/runs`、`GET /api/runs/{id}`、`POST /api/runs/{id}/replay` | 打开运行记录屏幕 |

## 2. 全局框架

### 2.1 顶栏

左：`SimuBench — <测试台名> | <屏幕名>`（总览、网络、通信、故障、运行记录，或仪表名）。右：`<状态> · <时钟> · t = <虚拟时间>`。

| 状态（D44） | 条件 | 显示 |
| --- | --- | --- |
| 等待命令 | 命令时钟或步进时钟，没有动作在执行 | `● 等待命令`（`muted` 点） |
| 执行命令 | 有动作在执行（`scpi` 写入后到回复前） | `● 执行命令`（`ok` 点） |
| 时钟走动 | 墙钟 | `● 时钟走动`（`ok` 点），时间每秒刷新 |
| 连接中 | 尚未连上或重连中 | `◌ 正在连接 <地址> …` |
| 已断开 | WebSocket 断开 | `✕ 已断开 · 只读 · N s 后重连`（`bad`） |

时钟：`命令时钟` / `步进时钟` / `墙钟`。测试台文件已改（D25）时，状态前加 `文件已改 · R 重建`（`focus`）。

### 2.2 底栏

左：当前焦点下可用的按键，格式 `<键> <动作>`，两个空格分隔，放不下时从右往左省略、最后一项为 `? 帮助`。右：`远程：无`，或 `远程：smu ← 脚本 :53122`（多个时 `远程：2 台`）。

### 2.3 屏幕与导航

```
总览 ──⏎──▶ 仪表屏幕（示波器为示波器屏幕）
  │  n ──▶ 网络 ──⏎──▶ 驱动端的仪表屏幕
  │  l ──▶ 通信（全屏）
  │  R ──▶ 运行记录
  └  f ──▶ 故障对话框（作用于当前焦点的仪表）
任一屏幕：Esc 返回上一屏（总览上无动作），q 退出（有本进程启动的服务时先确认）
```

## 3. 启动与连接

- `simubench tui <bench.yaml> [--clock …] [--seed …] [--idle …] [--hislip-port …] [--lang zh|en]`：在本进程启动服务（只监听 127.0.0.1，端口自动分配），打开会话后进入总览。启动时在 stderr 打印 SCPI 地址表（与 `serve` 相同），退出 TUI 前恢复终端再打印“已关闭会话”。
- `simubench tui --attach [URL] [--session SID] [--token …]`：URL 缺省 `http://127.0.0.1:8000`；只有一个会话时直接进入，多个时显示会话选择，没有时显示“这个服务上没有运行中的测试台。用 Web 或 `simubench tui <bench>` 打开一个。”。
- 令牌：`--token` 或环境变量 `SIMUBENCH_TOKEN`；401 时显示“访问令牌无效：用 --token 或 SIMUBENCH_TOKEN 给出 serve 打印的令牌”，不重试。
- 未安装 Textual：`simubench tui` 打印“终端控制台需要可选依赖：pip install 'simubench[tui]'”，退出码 2。

### 4.1 卡片网格

- 卡片宽 32 列，列间距 2；列数 = `floor((W + 2) / 34)`，100 列为 3 列。同一行卡片等高（取该行最高的）。
- 顺序：测试台文件中的 `instruments`，再 `parts`；编号 1–9 依次给前 9 张，第 10 张起无编号（用方向键）。
- 标题：`<编号> <实例名> · <型号>`（仪表）或 `<编号> <实例名> · <标签> · DUT`（元件；有 `label` 时用标签，DUT 标记在 `dut: true` 时出现）。
- 卡片放不下时，网格区域可上下滚动，通信记录至少保留 6 行。

### 4.2 卡片内容

每行以“标签 值”书写，超出宽度以 `…` 截断。仪表卡片固定结构：

| 行 | 内容 | 数据 |
| --- | --- | --- |
| 1 | `*IDN?` 身份 | `InstrumentInfo.idn` |
| 2…n | 按类别模板（下表） | `display.template`、`display.summary`、`display.channel_summary`、`state`、读数 |
| 连线 | `连线 <端口> <方向> <对端>`，多端口用三个空格分隔，未接为 `—` | `ports[].net` → 该网络的其他成员（见 4.3） |
| 错误 | `错误 <队列条数>`；大于 0 时 `错误 N · 最近 <最新代码>` | `errors` |

| 类别模板 | 第 2…n 行 |
| --- | --- |
| `oscilloscope` | 打开的通道一行一条：`CHn 开 <档位>/div <耦合>  <缩略图 6 字符>`（缩略图取所连网络的 `/levels` `wave`）；关闭的通道合并为一行 `CH2 关  CH3 关  CH4 关`；`时基 <scale>/div · 运行|停止|等待触发`；`触发 <源> ↑|↓ <电平> <方式>` |
| `function_generator` | 每通道一行：`CHn 开|关 <波形> <频率> <幅度>`；`负载 CH1 <负载设定> · CH2 …` |
| `smu` | `源 <功能> <设定> 输出 开|关`；`测 <电压读数> <电流读数>`；受限时 `CC 受电流限值 <限值>`（或 `CV 受电压限值`），`CC`/`CV` 为 `bad` |
| `multimeter`、`calibrator` | 面板的每个读数一行：`<标签> <读数>`（`display.panel.readouts`，`when` 不满足的不显示） |
| 其他（无模板） | `display.summary` 中的状态变量，每行一个 `<标签> <值>`；没有 summary 时取前 4 个非只读状态变量 |

元件卡片：第 1 行为主要参数（`params` 中带单位的，最多 3 个，`R 1.000 kΩ · C 100.0 nF`）；之后每个端口一行：`<端口> ←|→ <对端>  <网络有效值> <缩略图 4 字符>`（有效值取 `/levels` 的 `rms`，直流网络取 `dc`）。

### 4.3 连线的对端怎么写

一个端口所在网络的其他成员，按“仪表端口 → 元件端口 → 配件端口”排序，用 ` · ` 连接，最多两个，超出写 `+N`。配件端口写配件的显示名而不是内部名：`wire1.passive_probe0.IN` 写作 `10x 探头.IN`（`<衰减>x 探头`、`<值> 衰减器`、`<值> 负载` 等，由配件类型的 `label` 与主要参数生成）。卡片中，连线经过配件时直接写到配件另一端的端点，并附 ` · <配件名>`：`CH1 ← rc.OUT · 10x 探头`。

### 4.4 按键

| 键 | 动作 |
| --- | --- |
| `1`–`9` | 焦点移到第 n 张卡片 |
| 方向键、`Tab` / `Shift+Tab` | 在卡片间移动（方向键按网格，Tab 按顺序） |
| `⏎` | 打开焦点卡片：仪表 → 仪表屏幕（示波器 → 示波器屏幕）；元件 → 网络屏幕并选中它的第一个网络 |
| `␣` | 焦点仪表的输出：只有一个输出开关时直接弹出确认（第 10.1 节）；有多个时先弹出列表选通道。输出开关 = 名为 `output`、`output.enabled` 或 `ch<n>.output` 的布尔状态变量。没有输出的仪表：底栏提示“这台仪表没有输出开关” |
| `?` | 焦点卡片上有问题（错误、受限、跳闸、故障）时打开原因（第 9 节），否则提示“这张卡片没有需要说明的状态” |
| `f` | 对焦点仪表注入故障（第 8 节） |
| `n` `l` `R` `a` `q` | 见第 2.3 节与第 11 节 |

### 4.5 通信记录（嵌入）

见第 7 节的行格式；总览中显示全部仪表最近的记录，最新在下，自动跟随；标题右侧为总条数。

### 5.1 结构

自上而下，所有仪表相同：

1. **身份框**（全宽）：`ID <idn>`、`地址 <address_virtual>`（有 HiSLIP 时另起一行 `HiSLIP <address_hislip>`）；右侧 `定义 <definition_id>`、`错误 <条数> · 最近 <代码> <文字>`。有 `address_real` 时右侧加 `真实 <address_real>`。
2. **通道区**：每个通道一个框（无通道的仪表一个框），框内按类别模板分列（5.2）；框底一排按钮；框内最后一行在有问题时写“原因”行（5.4）。右侧并排两个窄框：**连线**（本通道的每个端口 `<端口> <方向> <网络>`）与**负载**（网络上的其他成员：元件写名称、DUT 标记、主要参数；仪表写 `<实例>.<端口>`；最后两行写网络 id 与电平）。
3. **其他设置**（可选）：模板没放进通道区的状态变量，按 5.3 分组，每组一行到三行。
4. **错误框**：当前错误队列（`errors`，最新在下）与“已读走”的错误（来自事件历史中这台仪表的 `error` 事件、而已不在队列中的），已读走的灰显并写读走它的命令与来源。
5. **通信记录**：只含本仪表。

通道多、放不下时，通道区上下滚动；`PgUp` / `PgDn` 按通道翻页。

### 5.3 控件

| 状态变量 | 控件 | 操作 |
| --- | --- | --- |
| 布尔 | 开关 | `␣` 切换；`dangerous` 或 `electrical` 为真时先确认 |
| 有 `options` | 选择 | `⏎` 弹出选项列表（显示 `option_labels`），↑↓ 选、`⏎` 写入 |

### 5.4 “原因”行

通道框内的“原因”行**由 TUI 根据已有数据生成**，不需要 #174：

| 情况 | 依据 | 文字 |
| --- | --- | --- |
| SMU 受限 | 读数 `core.limited` 为真、`core.regulation` | `原因  电流达到限值 <限值>，电压降到 <实际>（设定 <设定>）`；CV 受压同理 |
| 输出被故障关闭 | `/faults` 中作用于本仪表、`kind: trip`、`status: active` | `原因  故障 <id> 跳闸（<来源>）：<描述>` |
| 通信故障生效 | `/faults` 中 `timeout` / `disconnect` / `garble` / `latency` / `busy` 为 active | `原因  通信故障 <id>（<来源>）：<描述>` |
| 示波器通道无信号 | `/screen` 的 `traces[].silence` | 见第 6.3 节 |

完整的因果链（谁、何时、哪条命令）在第 9 节的原因对话框中，依赖 #174 与 D37。

### 6.1 波形区

- 宽 = 屏幕宽 − 27（右侧设置栏 26 列 + 间隔），高 = 屏幕高 − 2（栏）− 6（通信记录与边框）；100 × 32 时为 70 × 16 字符 = 140 × 64 点。
- 请求 `GET …/screen?points=<点阵宽度>`，服务端按每个点阵列返回最小值与最大值（与 Web 的像素抽取相同，architecture.md 8.3）；这是新增参数，缺省时行为不变。
- 网格：水平 10 格、垂直 8 格，格线为每 4 点一个点（`muted`）；中线不加粗。
- 纵向：每通道按自己的 `scale` 与 `offset` 换算到格；超出屏幕的部分贴边画（顶 / 底一行），并在标题中写 `CH1 超出屏幕`。
- 多通道叠画，后画的覆盖先画的；颜色按通道。
- 标题：左 `CHn <档位>/div · <时基>/div`（只写打开的通道），右 `运行|停止|等待触发 · <触发方式> · 采集 <acquisitions>`。

### 6.2 设置栏

自上而下：时基、延迟、触发（源、沿、电平、方式、耦合）、采集（方式、分辨率、存储深度）、每通道两到三行（开关与档位；耦合、输入阻抗、探头设定；连线对端与配件）。焦点可在每一项上移动，编辑规则同 5.3。底部两个按钮：`运行/停止 r`、`单次 s`（`POST …/panel`，D32）。

| --- | --- |

### 7.1 行格式

`<时间 13> <来源 12> <仪表 7> <命令 26> <结果>`，超出宽度截断（全屏时 `⏎` 展开当前行）。

- **一条命令一行**：同一客户端对同一仪表的 `scpi` `write` 与紧随其后的 `read` 合并为一行；写入后没有读取的显示 `·`；读取的回复以 `→ ` 开头。中间被别的事件隔开也照样合并（按客户端与仪表配对，等待最多 1 s 虚拟时间或到下一条写入为止）。
- **错误**：命令引起的 `error` 事件（同一仪表、同一时刻、紧随该写入）合并进该行，显示 `✗ <code> <message>`；有 #174 的分类时，在全屏视图中下一行缩进显示提示（第 9.2 节）。
- **二进制块**：`→ <前 12 字符>…  <size 千分位> B`，全屏中 `⏎` 展开为十六进制（每行 16 字节，最多 64 行，“还有 N 字节”）。
- **其他事件**（来源一律显示为对应来源或“事件”）：`state`（非 SCPI 引起的设置改变）→ `面板：<标签>` `<旧> → <新>`；`panel` → `面板：运行|停止|单次`；`fault` → `故障 <id> 生效|结束` `<描述>`；`acquisition` → `采集 #<n>`；`advance` → `推进 <dt>`；`remote` → `本地接管` / `脚本收回`。嵌入的记录只显示 `scpi` 与 `error`；全屏默认全部显示，`e` 只看错误。

### 7.2 全屏（`l`）

- 列标题一行；`t` 在虚拟时间与真实时间之间切换（列标题随之写“时间（虚拟）/（真实）”）。
- `/` 过滤：输入框在底栏上方，空格分隔的词全部匹配（仪表名、来源、命令文字、`error`），`Esc` 清除。
- 新记录到达时：在底部则跟随，向上翻看时不跟随并在标题右侧显示“N 条新记录 · End 跟随”。
- 只在内存中保留最近 10 000 条；更早的显示一行“更早的记录在运行记录中（R）”。

### 9.1 对话框

```text

┃   负载  r1 1.000 kΩ（HI → net-0 → r1.A）                     ┃
┃   结果  15.000 V / 1.000 kΩ = 15.00 mA > 10.000 mA           ┃
┃         实际 10.000 mA × 1.000 kΩ = 9.9990 V                 ┃
┃                                                              ┃
┃ ⏎ 跳到那条命令   c 复制   Esc 关闭                           ┃
┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛
```

- `?` 打开，内容依焦点而定：受限、跳闸、错误码、无信号、某个读数（“为什么是这个值”，D37）。
- **第一行**是一句话结论；之后每条依据一行或两行：值、出处（状态变量路径或网络）、来源（`← <时间> <来源> <命令>`，或 `← 测试台文件 <JSON 指针>`，或 `← 故障 <id>`）。
- 来源追溯规则（TUI 自己完成）：一个设置的当前值来自事件历史中最后一个改变它的 `state` 事件（找到引起它的 `scpi` 写入则写那条命令）；没有这样的事件时来自测试台文件。
- 结论与计算行（如“15.000 V / 1.000 kΩ = 15.00 mA > 10.000 mA”）来自引擎的因果解释（D37）；接口还没有给出时，只显示设定、限值与读数三行，不由 TUI 自己计算物理量。
- `⏎` 跳到通信记录中那条命令（全屏、选中该行），`c` 把全部内容复制为纯文本，`Esc` 关闭。

## 12. 远程控制与只读

被脚本远程控制的仪表（`InstrumentInfo.remote` 非空、`local` 为假），仪表屏幕顶部（身份框之上）出现一行：

```text
 smu 正被 脚本 :53122 远程控制：设置只读。L 本地接管（脚本下一条命令会收回）
```

- 所有设置控件只读（按钮灰显），`:` 控制台可发查询但写入被拒绝时显示服务端的 409 说明；`L` 本地接管先确认（10.1）。
- 总览卡片标题后加 `· 远程`（`muted`）。
