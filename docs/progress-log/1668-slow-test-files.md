## 三个最慢的测试文件提速（Issue 1668）

完成条件：不删除、不弱化任何断言；耗时下降来自消除重复工作，而不是减少检查。

- `acceptance/test_lfcal_agent_scenario.py`（27 s → 14 s）：5 个用例各自重搭一遍“agent 用 MCP 搭台”（约 3 s），其中 3 个各自再跑一遍 30000 点的脚本（约 3.5 s）。现在搭台在 module 作用域夹具里只做一次（`_build` 的断言原样保留），“脚本跑通 + 日志 + 严格仪表的 -113 + 同种子再部署逐位相同”三个本是同一流程的用例合成一个流程用例（D49、#704）；`assert` 43 条对 43 条，仅 `first == second` 改写成等价的 `(resp, table) == …`。
- `tests/test_pytest_plugin.py`（14 s → 6 s）：10 次 `runpytest_subprocess` 各付 ~1.4 s 的解释器与导入启动，子进程隔离本身是被测行为（#651 保留）。环境与命令行相同的场景合并进同一次子进程（10 次 → 4 次），内层每个用例的结果按名字逐个断言（`per_test`，读 `-rA` 摘要），原有的消息断言都保留。
- `tests/test_scope_trigger.py`（10.8 s → 4.1 s）：噪声触发路径的宽度搜索对 4095 条谱线的脉冲串逐点二分边沿，每一步 `Signal.sample_rel` 都重算每条谱线在基准时刻的相位（`phase_cycles` 21245 次、5.7 s）。`Signal` 现在缓存最近一个基准时刻的各线相量（`_lines_at`，只读数组）；计算本身不变，结果逐位相同。`Signal` 是值对象（运算都返回新对象），缓存不会失效；示波器记录、计数器等也走这条路径，一并受益。

自检（本机沙箱，`-n 4`）：`scripts/check.sh` 通过，5379 个 Python 用例（合并掉 8 个）、405 个 web 用例；全量 pytest 116.7 s → 108.7 s。三个文件单独跑合计少约 28 s CPU，但全量墙钟只降约 8 s（xdist 按模块分配、其余不属于这三个文件的测试仍占大头）。#1668 的 75 s 目标仍未单靠这些达到。
