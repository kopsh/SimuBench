| 目标 | 一句话 | 现状 |

| G1 下游软件对着虚拟仪表开发 | 硬件样机没出来，上位机、驱动、校准程序先开发 | 平台能力齐（样板 `examples/lowfreq-cal/`）；没有一台自研仪表；用例不能对真机运行；非 Python 上位机未实测；服务只监听本机 |

**深存储的机制：读多少算多少**（产品负责人 2026-11-13）。仿真不必像真机那样真的采下每一个点，也不追求把整条记录算完；把机制告诉使用者即可。

| 用法 | 机制 | 耗时 |
| --- | --- | --- |
| 等待：长时基、平均、扫描、建立时间 | 虚拟时钟直接跳过（已具备，D12） | 不占真实时间 |
| 采集命令（`:DIGitize`、单次、运行） | 只确定记录的参数（采样率、点数、触发点），不生成采样 | 与存储深度无关 |
| 读一段波形 | 只算被读到的那一段：帧是请求的纯函数，任意一段可单独算出 | 与读回的点数成正比 |
| 取测量值 | 稳态信号解析求值；必须看采样的测量按块读，不整条装进内存 | 多数与存储深度无关 |
| 屏幕与内部探针 | 只算每个像素的最小/最大值 | 与存储深度无关 |
| 把整条 2 Gpts 记录读回 | 按块算、按块发；能用，不设速度目标 | 与点数成正比，现在约 660 万点/秒（实测，单核） |

完成条件里的速度只有一条：读回 100 万点以内，采集加读回 2 s 内完成，与存储深度无关。多核并行与编译内核不在范围内，等有人真的需要整条读回再议。

**怎样告诉使用者**（#1012 的一部分）：

- `docs/real-models.md` 写一节“深存储是怎样仿真的”，就是上表；各示波器型号的覆盖表在存储深度的条目下指向它；
- P1-6 的使用说明里一句话：记录是读的时候才算的，整条读回的耗时与点数成正比；VISA 的超时按真实时间算，整条读回大记录时要相应调大；
- 界面上，示波器的存储深度旁标注同一句话的短版本（现有的保真度标注 ≈）。

**要让使用者知道的另一点**：没有真机对照之前，“与真机一致”只是“与手册一致”（H6，这台仪表比别的型号更难借到）。

### 4.1 设想的目标仪表

两个判断决定了下面的规格：

1. **示波器**的竞争点从带宽与采样率转到有效位数、噪声与数字处理功能；前端差异变小，ADC 之后的算法差异变大。
2. **频谱仪**变成宽带矢量信号分析仪：扫频迹线只是一个视图，主体是 IQ 采集、解调与标准测量应用。

每类三档。档位是**能力的台阶**，不是具体型号。

| 示波器 | O1 主流 | O2 高性能 | O3 旗舰 |
| --- | --- | --- | --- |
| 带宽 | 1–2 GHz | 8–25 GHz | 60–110 GHz |
| 采样率 | 5–10 GSa/s | 40–100 GSa/s（交织） | 256 GSa/s |
| 垂直分辨率 | 12 位，高分辨率模式 16 位 | 12 位 | 10–12 位 |
| 存储深度 | 500 Mpts–1 Gpts | 2–4 Gpts | 2–4 Gpts |
| 通道 | 4/8 模拟 + 16 数字 | 4 模拟 | 4 模拟，多台同步 |
| 触发 | 全数字：边沿、脉宽、欠幅、码型、区域 | 加串行码型触发 | 同 O2 |
| 采集 | 分段存储、历史回看 | 同 O1 | 同 O1 |
| 数字处理 | 数学通道、FFT 与频谱视图、光标、自动测量 | 加去嵌、眼图、抖动分析 | 同 O2 |
| 指标的写法 | 噪声、直流增益精度 | 有效位数随频率的曲线、交织杂散 | 同 O2，加通道间时延 |
| 数据出口 | 二进制波形块 | 加高速流式传输 | 同 O2 |

| 频谱/信号分析仪 | A1 经济型 | A2 高性能 | A3 旗舰 |
| --- | --- | --- | --- |
| 频率范围 | 9 kHz–8 或 26.5 GHz | 2 Hz–50 GHz | 至 110 GHz，扩频头至 170 GHz 以上 |
| 分析带宽 | 40–160 MHz | 2–4 GHz | 8–10 GHz |
| 实时带宽 | 40–100 MHz | 约 1 GHz | 2 GHz 以上 |
| 相位噪声（1 GHz，10 kHz 偏移） | 约 −105 dBc/Hz | 约 −135 dBc/Hz | 同 A2，互相关后更低 |
| 架构 | 超外差 + 数字中频 | 加宽带直采路径 | 多通道相参接收 |
| 迹线功能 | 多标记、噪声标记、通道功率、邻道功率比、占用带宽、零扫宽 | 同 A1 | 同 A1 |
| 信号分析 | IQ 采集、模拟解调 | 数字解调与 EVM、标准测量应用 | 加互相关 |
| 指标的写法 | 噪声底、三阶截点、平坦度 | 加残余 EVM、宽带无杂散动态范围 | 同 A2 |
| 数据出口 | 迹线、IQ 块 | 加 IQ 长时间流 | 同 A2 |

### 4.3 阶段

每个阶段的完成标志是同一种形式：**一台设想仪表的定义能加载，一份用到该档关键功能的脚本通过。**

| 阶段 | 内容 | 依赖 | 完成后能仿真 |
| --- | --- | --- | --- |
| 1 指标级 | C4、C5、C6 | — | O1 与 A1 的**稳态部分**：指标按数据手册出现，常用测量可用 |
| 2 时域与复包络 | C7、C9；C8 余下的触发类型与历史回看；C10 | 阶段 1；先写设计（4.5） | O1 完整（除数字通道）；A1 完整（除实时）；A2 的 IQ 采集 |
| 3 规模 | C11、C12、C13 | 阶段 2；按性能分析决定（4.6） | O2、A2 的采集与传输 |
| 4 多通道与可变结构 | C14、C15、C16 | 阶段 2 | O3、A3；O1 的数字通道 |
| 应用层（按需） | C17：经算法托管接入 | H5、P4-1 | O2、A2 的分析功能 |

阶段 1 可与第 3 节并行，但第 3 节的核心项优先。上表是能力的依赖关系；示波器这条线的实际顺序以 4.0 节为准（C11 中示波器的按块计算提前到阶段 2 之前，它不依赖新的信号表示）。频谱仪的阶段 3、4 做不做取决于 H7。

### 4.4 阶段 1 的拆分（可直接开 issue）

全部是能力建设，标签 `核心`；每项被一台 `sb-*` 设想仪表实际使用（D50，块覆盖测试）。

| 编号 | 内容 | 依赖 | 完成条件 |
| --- | --- | --- | --- |
| F1-1 | 通用 ADC 的非理想：有效位数随输入频率的曲线（声明若干点，按频率插值为附加噪声）、积分非线性（声明多项式系数，在量化之前施加） | — | 未声明时现有型号的回复逐位不变；对单音输入，由采集数据算出的信纳比与声明的曲线在写明的容差内一致，容差的来源写明 |
| F1-2 | 交织失配：子 ADC 的增益、偏置、时延失配，产生位置可预先算出的杂散 | F1-1 | 杂散的频率与幅度和解析式一致；失配为 0 时回复不变 |
| F1-3 | 示波器数学通道：加、减、乘、FFT（复用 #955 的窗与 FFT 纯函数），按采样流实现 | — | 一台 `sb-*` 示波器的 FFT 迹线，对已知单音的峰值频率与幅度和窗的解析修正一致；超出 FFT 上限时拒绝 |

### 4.5 阶段 2 之前要先定的设计

阶段 2 改的是信号表示，影响文件格式与全部读信号的组件，属于要写决策的范围（修改 D67，不新增条目）。先写设计，再拆 issue。设计要回答：

1. **时域信号源怎样进入解析的模拟域。** 方向：信号描述增加“有限长记录”的叶子，经线性网络时用频域方法（记录的 FFT 乘传递函数）。要定：记录长度的上限与拒绝规则；它与稳态谱线叠加时的求值；非线性器件怎样处理。
2. **带通信号怎样表示。** 方向：叶子为“中心频率 + 复包络”，复包络是周期的或有限长的采样序列；线性网络只在包络带宽内求值。要定：包络采样率与带宽的关系；经混频器后的中心频率平移；与现有调制（AM/FM/PM 展开为谱线）的关系，哪些保留解析。
3. **保住三条不变量。** 同一时刻两次读取相同；被动读取不改变仿真（D55）；超出能力时拒绝而不是截断。
4. **不做什么。** 不做电路级瞬态求解（非线性器件的时域积分）；这条边界在 D67 的“备选一”里已经划过。

完成条件：设计文档经产品负责人确认；现有全部金标准在新表示下回复不变。

### 4.6 阶段 3 的判断方法

不预先决定用 Rust 重写哪一部分。先做两件事，再按结果拆：

- 给 `sb-dso-o1` 的 1 Gpts 采集与 `sb-sa-a1` 的 160 MHz IQ 采集各写一个基准测试，记录耗时与内存的分布；
- 把“一帧整块计算”改为“按块计算、逐块交付”，上限从“帧的点数”改为“同时在内存里的点数”。示波器的这一步已提前（4.0 节第 2 步）。编译实现（D19 的边界）只在有人真的需要、且这一步之后仍然慢时才做。

## 5. G3 验证算法与架构（等 H5）

算法托管、定点、金标准比对、链路预算没有外部收益，**等 H5 之后再做**，否则会做成没有人用的通用框架。
接口约束已经留好（signal-chain.md 第 8 节）。H5 之后按验证清单的实际内容从下面选，每项先写设计再拆 issue：

| 编号 | 内容 | 对应清单里的哪类问题 |
| --- | --- | --- |
| P4-1 | 算法托管：把一个块换成工程师自己的实现（Python 插件先行，C/C++ 动态库其次），接口即 `frames(port, request)` 与模块级纯函数 | “我的滤波器 / 检波算法放进去对不对” |
| P4-2 | 金标准比对：与工程师提供的向量逐点比对，报告第一处不同 | 同上，以及“与 MATLAB 模型差多少” |
| P4-3 | 定点数据类型：位宽、舍入与饱和；同一块在浮点与定点下运行并比对 | “截断后差多少、会不会溢出” |
| P4-4 | 链路预算：由各块的声明参数算级联噪声系数、增益、截点、动态范围，与采样流仿真互相核对（`engine/rfcascade.py` 已有级联指标） | “ADC 用 12 位还是 14 位、增益怎么分配” |

验收者必须是算法或架构工程师（D11），不是产品负责人，也不是 agent。
“单次毛刺能不能被抓到”一类问题属于 C7，在阶段 2 做，不等 H5。

## 6. 不做的

- 授权与计费、对外发布、协作平台、私有化部署平台、公有云形态（D17）。
- 电路级瞬态仿真（SPICE 的范围）、HDL 仿真、通用的系统仿真平台（MATLAB/Simulink、GNU Radio 已经成熟）。
- 完整的通信标准解调与协议栈、协议解码、眼图与抖动分解：算法团队已有模型的，经算法托管接入（P4-1）；平台只提供 IQ 与波形数据、测量结果的命令入口。
- 光与太赫兹器件的物理：扩频头只按“变频损耗、噪声系数、频率平移”的功能块建模。
- 按厂商的真实电路建模：内部结构是功能框图级。

## 8. 交给 agent 时的规则

- 一行一个 issue；标题写用户可见的变化；正文抄“内容”与“完成条件”两栏，并写明依赖的 issue 编号。标签按表（`核心` 只由主 agent 做，`可认领` 任何 agent 可认领，见 AGENTS.md）。
- “实测记录”“卡点记录”“验证清单”只记录真实发生的事：agent 不替工程师填实测结果，不替算法工程师写验证需求；卡在某个 H 上就写明，不用假设的数据补。
- 每个新功能块必须被一台内置型号或 `sb-*` 仪表实际使用；完成条件写成与解析式或独立计算比对（architecture.md 10.2），不靠“看起来像”。
- 每完成一项，在 progress-log.md 末尾追加自检表，并修改本文对应的行（删去或改“现状”）。新的计划加进本文，不另开文档。
