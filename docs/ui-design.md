# 界面设计

状态：生效（D22、D23、D24）。本文定义 Web Bench 的界面参考、布局、视觉语言与交互规范；实现以设计令牌与组件库为准。

## 1. 参考软件与借鉴点

跨领域选取在“专业用户、高信息密度、长时间使用”上做得好的软件，按要解决的问题借鉴：

| 要解决的问题 | 参考 | 借鉴点 |
| --- | --- | --- |
| 多台仪表的组合与信号路由 | Liquid Instruments Moku（多仪器模式）、NI InstrumentStudio | 仪表以卡片/面板呈现，路由关系可视化；仪表面板与连接关系同屏 |
| 现代仪表软件的观感与波形 | Saleae Logic 2、Keysight PathWave BenchVue | 深色为主的测量界面；时间轴缩放平移顺滑；测量值与波形并列；克制的配色 |
| 节点与连线的画布 | Figma、Blender 节点编辑器、Unreal Blueprint、Node-RED | 端口按类型着色；连线吸附与高亮；画布 + 右侧检查器；小地图；对齐与自动布局 |
| 电路与拓扑 | KiCad、LTspice、Simulink | 端口方向与介质明确；网络高亮；在连线上标注配件；模块可“打开”查看内部 |
| 工作台布局 | VS Code、JetBrains IDE | 左侧资源管理、中央编辑区、右侧检查器、底部面板（问题、输出、终端）；命令面板；全部可用键盘完成 |
| 校验与诊断 | VS Code“问题”面板、TypeScript 编译诊断 | 诊断列表与画布位置双向定位；错误码 + 说明 + 快速修复 |
| 通信记录 | Wireshark、Chrome DevTools 网络面板 | 列表 → 详情 → 原始字节三级查看；过滤与着色规则；时间列可切换（虚拟/真实） |
| 时间线与回放 | Chrome DevTools 性能面板、Rerun、Foxglove Studio | 统一时间线上叠放命令、状态变化、事件；拖动时间游标回看任意时刻；面板布局可保存 |
| 时钟控制 | 数字音频工作站（Ableton Live 等）的走带控制 | 顶部固定的运行/暂停/单步/倍速控件与时间显示 |
| 观测与指标 | Grafana、Datadog | 面板化布局、时间范围联动、清晰的空状态与无数据提示 |
| 细节与键盘体验 | Linear | 一致的快捷键、即时反馈、乐观更新、精致的过渡与焦点处理 |

## 3. 工作台布局

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ ◧ SimuBench  测试台：示波器-RC ▾   ● 运行中  ▶ ⏸ ⏭ 1×   t = 00:00:04.200   ⌘K │  顶栏
├──────┬──────────────────────────────────────────────────────┬───────────────┤
│ 资源 │                                                      │ 检查器        │
│ ──── │                  画布 / 仪表屏幕（标签页）            │ ───────────── │
│ 仪表 │                                                      │ 示波器 CH1    │
│ DUT  │   ┌ 函数发生器 ┐       ┌ RC ┐        ┌ 示波器 ──────┐ │ 档位 50 mV/div│
│ 连线 │   │ CH1 1 kHz  │──────▶│    │──10×──▶│  ∿∿∿         │ │ 耦合 DC       │
│ 网络 │   └────────────┘       └────┘        └──────────────┘ │ 真实值 ⓘ     │
│      │                                                      │               │
├──────┴──────────────────────────────────────────────────────┴───────────────┤
│ 通信 │ 事件 │ 问题 2 │ 时间线 │ 运行记录                                      │  底部面板
│ 00:00:04.200  scope  :WAVeform:DATA?  → #42000…  2007 B                       │
└─────────────────────────────────────────────────────────────────────────────┘
```

- **顶栏**：测试台名称与切换、运行状态、时钟控制（运行、暂停、单步、倍速）、虚拟时间、命令面板入口。
- **左侧资源栏**：测试台内的仪表、DUT、连线、网络的树形列表，与画布双向选中。
- **中央**：画布与仪表屏幕以标签页并存；画布可与一个仪表屏幕左右分屏。
- **右侧检查器**：选中对象的参数（可编辑）、状态、隐藏状态与真实值（受开关控制）、诊断。仪表的设置分层显示（#728）：定义的 `display.summary` 与所选通道的 `channel_summary` 在最前，有名字的不带路径前缀的设置紧随；其余按路径首段分组。分组默认展开的条件是：不是远程编程组（通信、波形传输、状态、系统、数据格式等），且多数设置有 `label`（定义作者当作旋钮的，如万用表的孔径、源表的自动量程）；没名字的设置（如示波器模板里没标注的测量槽与通信设置）与远程组默认折叠，没名字的不带前缀的设置归入“其他”。多通道仪表一次显示一个通道，用 CH 选择器（通道色）切换，不再上下堆叠；选择器不跟随画布的选中（#733）：工作台的 selection 只有对象与 id、不带通道号，画布上也没有可选中通道的交互，要做需先给 selection 加通道（`核心`），暂由检查器自己的 CH1 默认值承担。定义没有给名字的设置以等宽路径作名称；空槽（`NULL`、`NONE`）显示“无”，空枚举值显示“—”；测量槽 `measure.pN.*` 合成一行。分组只靠路径与已有的摘要字段，不改定义格式；是否上面板的逐项标记要等有需要时再做（格式变更）。
- **底部面板**：通信、事件、问题、时间线、运行记录；可折叠、可拖动高度。
- 布局（面板宽度、分屏、展开状态）按测试台保存在浏览器本地。
- 最小窗口宽度 1280 px；面向桌面使用，不做移动端布局。

## 4. 视觉语言

### 4.1 主题

- 深色与浅色两套主题，默认跟随系统；测量类屏幕（波形、频谱）在两种主题下都使用深色绘图区，与仪表习惯一致。
- 中性色为主，主色只用于主要操作与选中；功能色只表达状态。

### 4.2 颜色

| 用途 | 规则 |
| --- | --- |
| 通道颜色 | CH1 黄、CH2 青、CH3 品红、CH4 蓝（与主流示波器一致）；同一通道在卡片、迹线、连线、图例中颜色相同 |
| 端口介质 | 电压信号、参考时钟、触发分别用不同颜色与形状，连线继承端口颜色 |
| 状态 | 正常（绿）、警告（琥珀）、错误/过载/跳闸（红）、未知/断开（灰）；**始终同时显示文字或图标** |
| 仿真专属信息 | 真实值、隐藏状态、保真度标注使用独立的紫色系，与仪表本身的信息区分 |

### 4.3 字体与数值

- 中文：思源黑体（Noto Sans SC）；西文：Inter；数值与通信记录：等宽字体（JetBrains Mono），数字等宽，读数跳动时不抖动。
- 数值：工程单位与 SI 前缀（mV、µA、kHz）；有效位数与仪表分辨率一致；数值右对齐、小数点对齐；单位字号略小、颜色略淡。
- 中文排版：正文行高 1.6；中西文之间保留间距；按钮与标签不使用全角标点结尾。

### 4.4 密度

专业工具以中高密度为主：基准间距 4 px，控件高度 28–32 px，表格行高 28 px；检查器与通信记录提供“紧凑”选项。

## 5. 核心组件

| 组件 | 要点 |
| --- | --- |
| 仪表节点 | 标题（实例名 · 型号）、通道摘要、端口（按方向分列左右）、错误队列徽标；由仪表定义自动生成（D1）；示波器通道行带波形缩略图，收到 SCPI 命令时短暂闪烁（D44） |
| DUT 节点 | 标题、参数摘要、端口 |
| 连线 | 继承端口颜色；配件以小标签显示在连线中点（如“10×”）；悬停高亮整个网络并显示当前值；运行时按网络电平着色：有信号时以通道色从源向负载流动，0 V 时为灰色（D44） |
| 读数 | 数值 + 单位 + 状态；可固定到检查器顶部。计数器、万用表这类单读数屏幕按仪表前面板只放主读数与状态，屏幕下方留空，不为填满而编造内容（#316：读数历史/趋势要等有真实需求、并能说清它与仪表的统计功能如何区分时再立项） |
| 波形屏幕 | Canvas 绘制；网格与刻度；多通道叠加；缩放、平移；服务端按像素抽取（architecture.md 8.3）。下方是**测量表**：每个显示的通道一行 Vpp、频率、周期、均值、RMS，由服务端用该型号自己的自动测量规则（门限、顶/底、交叉电平）在屏幕上的那份记录上计算，停止后与脚本的 `:MEASure:*?` 读数相同，测不出时显示 —。**光标**按钮打开两条时间光标（距左边的格数）与两条电压光标（距中心的格数，按所选通道的 V/div），读出 Δt、1/Δt、ΔV。光标像真机一样在屏幕上直接拖动（拖竖线改时间、拖横线改电压），读数画在屏幕右上角；下方的滑块是同一组光标的键盘操作途径（#356）。光标只在界面上，不发送命令。顶部状态与画面来源一致：运行时写“实时画面”（刷新的画面不是采集），停止或单次后写“采集次数 n”（#280） |
| 频谱屏幕 | 迹线、标记、参考电平线、RBW/VBW 显示 |
| 通信记录 | 虚拟列表；列：时间、仪表、方向、命令/响应、字节数、耗时；过滤、搜索；二进制块以摘要显示，可展开十六进制 |
| 诊断项 | 级别图标、错误码、说明、位置链接、建议操作 |
| 时钟控制 | 运行/暂停/单步/倍速；步进时钟模式下显示“推进”按钮与步长 |
| 危险确认 | 命令名、目标仪表、影响说明；需显式确认 |

## 6. 交互规范

- **选中联动**：资源栏、画布、检查器、通信记录、时间线之间选中同一对象时互相定位。
- **命令面板**（⌘K / Ctrl+K）：所有操作可搜索执行；常用操作有快捷键并在菜单中标出。
- **编辑**：撤销/重做；自动保存草稿；显式保存为版本；外部修改（Agent、Git）时提示并显示差异。
- **反馈**：操作 100 ms 内有视觉反馈；超过 1 秒显示进度；可取消的长操作提供取消按钮。
- **空状态**：说明这里会显示什么，并给出下一步操作（如“从脚本生成测试台”）。
- **运行状态**：顶栏的“运行中”带上时钟的实际状态：命令驱动时钟下为“等待命令”或“执行命令”，墙钟下为“时钟走动”；悬停说明画面为什么不变以及怎么让它动起来（D44）。动效遵循 `prefers-reduced-motion`。
- **仪表屏幕的动效模仿仪表本身**（`web/src/lib/motion.ts`）：示波器运行时保留前 3 次采集逐渐变淡（余辉），新采集从左往右画入；频谱仪的新扫描在扫频线后重绘、线前仍是上一次扫描，速度随扫描时间（250–1200 ms）。减少动态效果时一次画完，e2e 截图以此模式运行。首页展示的仪表画面必须来自真实运行（D65），首页动效只用产品里真实存在的行为。
- **断开与重连**：与引擎断开时顶栏明确提示，界面进入只读，自动重连后恢复。
- **文案**：遵循 [glossary.md](glossary.md)；错误提示按“发生了什么 → 在哪里 → 怎么处理”。
- **数值调大调小**（#738）：数字设置不必每次输入。输入框右侧悬停或聚焦时出现一对加、减按钮；聚焦后 `↑`/`↓` 步进，`Shift` 加大十倍（梯度则一次一个十倍程）；聚焦后滚轮步进（未聚焦时滚轮仍滚动面板）。每一步立即写入，和回车一样走 `configure`。步长来自设置自己：有梯度（`1-2-5`、`1-3` 或列表）就走下一档，整数加减 1，连续量取当前数量级的十分之一（1.5 kHz 一步 100 Hz），到 `min`/`max` 为止，到头的按钮置灰。只读、被自动开关覆盖（显示“自动”）和断开时不可用。计算在 `model.ts` 的 `stepNumber`。
- **自动与手动设置**（#279、#283）：一个手动值有同名的自动开关（`bw.res` 与 `bw.res_auto`、`sweep.time` 与 `sweep.time_auto`、`sense.range` 与 `sense.range_auto`）且开关为开时，存储的手动值不生效：Web 检查器的该项置灰、值显示“自动”并注明“自动时不生效”（聚焦后显示并可编辑存储值）；TUI 的通用视图显示 `AUTO`。生效值只由仪表屏幕给出（频谱仪的 RBW/VBW/SWT 读数），两处不出现互相矛盾的数字。
- **内部结构图**（#739）：回答“这个组件起什么作用”。选中一个组件，图上亮出它的作用链：供给它的（信号连线与它使用的组件，直到面板输入）与它到达的（直到读数组件与面板输出），其余淡化；只经设置选通的关系（触发按 `trigger.source` 选源）没有连线，亮出时临时画一条点线，写明设置名，未选中本通道时置灰并注明当前值。右侧详情先说作用，再给参数：
  - **由什么控制**：每个跟随的设置一行（名称 · 当前值 · 写它的命令，通道号已填好；`X[?]` 可写可查、`X?` 只查、`X` 只写），同一设置还驱动别的组件时写“也驱动：…”（点击选中）；只运行操作、不写设置的命令列在“操作命令”。不跟随任何设置、只有操作命令的组件（系统块、状态寄存器）标题改为“只由命令操作”。
  - **影响哪些读数**：按回答查询的组件分组，每组写出路径（ADC 组 → 采集 → 波形传输，路径上的组件可点）：终端组件（不再供给别的组件，如波形传输、自动测量）在前并展开，本组件自己的查询其次，路上组件自己的状态查询（采集的采样率、触发状态）折叠为“途经组件的查询”——没有终端组件时展开。通道组件经过按设置选通道的组件时，注明“仅当某设置选中本通道时”与当前值。一组超过 6 条时收起其余。
  - 悬停一行，图上只亮出这一行涉及的组件或路径；行右侧的图钉把它钉住，再点取消；点空白处取消选中与钉住。
  - 工具栏的“查找命令或设置”：命令按仪表的规则匹配（长短形式、可省节点、通道后缀、`?`，输入时也按子串），设置按路径或名称；命中的组件在图上亮出，右侧列出结果，回车选中第一个，`Esc` 清空；选中折叠通道里的组件时自动展开该通道。
  - 视图只读（是否允许在图里改设置见 #801）；“由什么控制”里的设置行有“在检查器中定位”（#800）：选中该仪表，检查器切到该设置的通道（`chN.` 前缀）、展开所在分组，滚动到该项、聚焦并短暂高亮。这是一次**定位请求**（`store.ts` 的 `reveal`：仪表、路径与递增序号），不是 selection 的新形状：selection 仍只有对象与 id，画布、资源树、通信记录之间的选中联动不受影响，重复定位同一项靠序号照样生效。验收页没有检查器，不传 `onLocate`，不显示这个入口；其余交互都只在视图内部。
- **告警徽标**：UNCAL、过载等徽标只在条件成立时出现，悬停说明原因（UNCAL：扫描时间短于当前 RBW/VBW 所需时间）；不以灰色常驻。
