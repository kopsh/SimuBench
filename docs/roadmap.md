# 开发计划

状态：草案

## 原则

1. **纵向切片**：每个里程碑交付一条从 Bench 文件到界面、从脚本到运行记录都能走通的完整路径，而不是一层层横向铺开。
2. **商用标准，而不是演示**（D22）：每个进入界面的功能都按下文“界面质量标准”设计、实现与验收；宁可功能少，不做半成品。
3. **验收驱动**：每个里程碑以验证场景的自动化测试（architecture.md 第 10 节）与界面验收标准为完成条件。
4. **两条轨道并行**：引擎与接入一条轨道，产品设计与界面一条轨道；设计领先实现一个里程碑。

时长取决于团队规模，本文只给顺序与范围，不给日期。

## 界面质量标准（D22）

### 设计先行

每个功能进入开发前具备：用户任务与流程、线框图、高保真设计（含全部状态）、交互说明、验收清单。设计稿与组件库保持同步。

### 设计体系

- 在 shadcn/ui 之上建立 SimuBench 设计体系：颜色、字体、字号、间距、圆角、阴影、动效的设计令牌；浅色与深色两套主题。
- **仪表视觉语言**：通道颜色在仪表卡片、波形迹线、连线、图例中保持一致；状态（开/关、恒压/恒流、锁定/失锁、过载、错误）用文字 + 图标 + 颜色表达，不只靠颜色。
- 数值显示：工程单位与 SI 前缀（mV、µA、kHz）、有效位数与仪表分辨率一致、等宽数字对齐、单位与数值分开排版。
- 组件以 Storybook 管理，每个组件列出全部状态与变体。

### 完整的状态

每个页面与组件定义并实现：空状态（含引导下一步）、加载中、部分数据、错误（说明原因与处理方法）、与引擎断开后的重连、只读、危险操作确认。

### 交互

- Bench 画布：撤销/重做、多选、复制粘贴、对齐吸附、自动布局、缩放与小地图、快捷键、右键菜单；
- 全局命令面板与快捷键；所有操作可用键盘完成；
- 自动保存草稿 + 显式保存版本；文件在外部被修改（如 Agent 或 Git）时提示并显示差异；
- 长操作显示进度并可取消；
- 错误信息可操作：指出位置（Bench 中的哪个仪表、哪根连线），给出修改建议，与校验诊断（architecture.md 3.5）一致。

### 性能预算

| 场景 | 目标 |
| --- | --- |
| 打开一个 12 台仪表的 Bench | 2 秒内可交互 |
| 4 通道示波器屏幕实时刷新 | 60 帧/秒，不掉帧 |
| 50 个节点的画布拖拽、缩放 | 流畅，无明显延迟 |
| SCPI 通信记录 10 万条 | 虚拟滚动，搜索 1 秒内返回 |

### 可访问性与国际化

- 对比度符合 WCAG 2.1 AA；可完全用键盘操作；焦点可见；
- 中文与英文界面；所有文本外置；日期、数字格式本地化。

### 工程质量

- 组件测试、端到端测试（Playwright）、视觉回归测试；
- 前后端接口自动生成并在 CI 中检查（D21）；
- 本地服务安全：默认只监听本机；启动时生成访问令牌；校验 Host 与 Origin 请求头，防止网页通过本机地址访问服务（DNS 重绑定）；危险操作二次确认。

### 可用性验证

每个里程碑结束前，请至少 5 位内部工程师完成预设任务；记录任务完成率、耗时、出错点，问题进入下一里程碑。

## 里程碑

### M0 基础

**目标**：后续所有工作需要的工程与设计基础。

| 轨道 | 内容 |
| --- | --- |
| 工程 | 仓库结构（引擎、服务、前端、参考计算、验收测试）；Windows 与 Linux 的 CI；Python 与 TypeScript 的代码规范与检查；Pydantic → OpenAPI / JSON Schema → TypeScript 的生成流水线与一致性检查（D21）；内部软件包源发布流程 |
| 设计 | 信息架构（Bench 列表、Bench 画布、仪表屏幕、通信与事件、运行记录、设置）；核心任务流程；设计令牌与主题；仪表视觉语言；基础组件库（Storybook） |

**完成条件**：两个平台的 CI 通过；生成流水线可用；设计体系与核心流程线框图评审通过。

### M1 第一条纵向切片：函数发生器 → RC 低通 → 示波器

**目标**：证明“组件组合 + 物理正确求解 + 脚本不改即可使用”可行，并交付第一批商用质量的界面。

| 轨道 | 内容 |
| --- | --- |
| 引擎 | 组件模型核心（组件、端口、连线、网络、线性网络求解）；信号描述与三种求值方式；虚拟时钟（命令驱动 + 步进）；计数器式随机数；动作队列与运行记录 |
| 仪表 | 通用 SCPI 命令层与 IEEE 488.2 基础；函数发生器、示波器两个仪表定义；RC 低通 DUT；探头 |
| 接入 | PyVISA 后端（进程内）；SCPI 网络仪表；`simubench serve` |
| 验收 | 独立的参考计算模块；示波器场景中触发、解码、二进制块、确定性各组，以及按物理正确重算的转折频率组 |
| 界面 | Bench 列表；Bench 画布（只读展示：仪表卡片、DUT、连线与配件）；示波器屏幕；函数发生器面板；SCPI 通信记录；与引擎断开后的重连 |

**完成条件**：示波器场景对应测试在两个平台通过；一个未修改的 PyVISA 脚本只换资源管理器即可运行；界面通过 M1 的验收清单与可用性验证。

### M2 编辑、校验与 Agent

| 轨道 | 内容 |
| --- | --- |
| 引擎 | Bench 编辑操作与校验诊断；多通道（D15）；故障注入（通信层与仪表层）；墙钟模式 |
| 接入 | MCP 服务：查询定义库、创建与编辑 Bench、校验、由脚本生成 Bench、部署、发送 SCPI、读取通信记录 |
| 验收 | 示波器场景全部；多通道场景 |
| 界面 | Bench 画布编辑（添加仪表、连线、配件、撤销/重做、自动保存与版本）；校验诊断在画布上定位；Agent 修改的差异审阅；故障注入面板；参数编辑；仪表卡片自动生成（类别模板 + 通用布局） |

**完成条件**：Agent 可由一份脚本生成 Bench 并部署，工程师在画布上审阅后运行；界面验收与可用性验证通过。

### M3 仪表扩展

| 轨道 | 内容 |
| --- | --- |
| 引擎 | 非线性求解（带限值的源、电子负载）；数值路径（FFT、数值解调）；能力上限与截断规则；动态状态的精确推进 |
| 仪表 | 锁相放大器、频谱分析仪、射频信号源、SMU、电子负载、万用表 |
| 验收 | 锁相放大器、频谱分析仪、射频信号源、SMU 场景全部 |
| 界面 | 频谱仪屏幕（迹线、标记）；锁相放大器屏幕（读数与建立曲线）；SMU 屏幕（IV 曲线、缓冲区表格）；射频信号源面板；参考/时基连线的展示 |

**完成条件**：6 个验证场景全部通过；新仪表的界面全部由仪表定义自动生成（类别模板），不含型号专用代码。

### M4 可观测性

| 轨道 | 内容 |
| --- | --- |
| 用户可观测 | 虚拟探针；因果解释；保真度标注；时间线；运行记录回放与对比；真实值开关（D9） |
| 运维可运维 | 结构化日志；指标导出；产品改进信号；版本清单；`doctor` 健康检查；诊断包；内部遥测收集（D17） |
| 界面 | 探针工具；“为什么是这个值”的解释视图；统一时间线；回放与对比视图；诊断包导出 |

**完成条件**：任一读数可在界面中追溯来源；一次 CI 失败可在本地回放并在界面中定位；运维数据进入内部收集服务。

### M5 内部发布与定标场景

| 轨道 | 内容 |
| --- | --- |
| 定标能力 | 组件层误差与定标系数；仪表实例身份（序列号、固件）；虚拟校准台账；真值判定（D6、calibration-notes.md） |
| 产品化 | 安装与升级；Bench 与定义文件格式的版本迁移；用户文档与示例；pytest 插件；性能与稳定性测试；安全检查 |
| 界面 | 定标相关视图（隐藏误差、系数、as-found / as-left 判定结果）；首次使用引导；设置与偏好 |

**完成条件**：产品负责人完成定标场景验收（D11）；内部发布。

### 之后

- 类别模板与“技术指标 → 误差参数”映射（D3 第 2 层）；
- 录制波形文件（D14）；
- 仪表内部组件图的编辑（D3 第 3 层）；
- TUI；更多通信协议（VXI-11、HiSLIP 等）；
- 协作、资产库、私有化部署平台；
- 对外发布：授权、遥测默认关闭（D17）。

## 需要确认

1. 团队中是否有专职产品设计师？商用质量的界面需要设计先行；若没有，设计工作由谁承担。
2. 是否有既定的品牌规范（标志、颜色、字体）需要纳入设计体系。
3. 首批界面语言：中文为主、英文为辅，还是两者同时完整提供。
